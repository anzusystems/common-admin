## 1. Breaking changes and migration

### 1.1 Entry points and package layout
- `@anzusystems/common-admin/labs` is gone; everything it exported is exported from `@anzusystems/common-admin` under the same name, and the old main-entry variants of those names are deleted, so each name means the labs one (`e8494f3a`, `1463ce82`). Migration: replace `/labs` imports by the main entry; code written against the old 1.x filter / datatable / autocomplete / subject-select API has to move to the labs API (`createFilter` + `createFilterStore` + provide/inject, `name` props instead of `v-model` + `makeFilterHelper`).
- Explicit `exports` only: `.`, `./styles`, `./e2e`, `./eslint`, `./oxlint`, `./testing`, `./vite`, `./package.json`; the `./*` wildcard is gone, deep imports no longer resolve (`f432fda1`, `66fa6f07`, `aef095d0`).
- `dist/` is one file per module (`preserveModules`, bundled deps under `dist/vendor/`), `"sideEffects": ["**/*.css"]`, one `.d.ts` per module; module augmentations target `vue` instead of `@vue/runtime-core` (`f432fda1`, `aef095d0`).
- `"module"` points at `dist/common-admin.js` (was the never-emitted `common-admin.es.js`) (`c9e48e58`).
- Sources are laid out by domain (`src/domains/<domain>/…`, `src/shared/`, `src/plugins/`); nothing is named `labs` any more (`85417526`, `003f884f`).
- The vitepress docs site is gone; docs are plain markdown in `doc/guide`, `doc/editor`, `README-DEV.md` (`4d86ae80`, `d3003146`).

### 1.2 Plugin setup, i18n, alerts, styles
- i18n: the plugin takes the admin's own `i18n` instance (`app.use(AnzuSystemsCommonAdmin, { i18n, … })`, composition mode) and translates through it; the admin's locale files keep including `messagesSk` / `messagesEn` / `messagesCs`. `i18n` and `useI18n` are no longer exported (import `useI18n` from `vue-i18n`); `modifyLanguageSettings` switches the locale only once the language's messages are loaded; the library's `DefineLocaleMessage` augmentation is not published; a missing `i18n` warns (`aef095d0`, `dde10e10`, `f576ca13`).
- Alerts: `AAlerts` renders through Vuetify `VSnackbarQueue` (was `@kyvg/vue3-notification`): max 5 visible, newest pushes out the oldest, alerts raised before the host mounts wait for it. Mount exactly one host, outside any layout switch (`ALayoutSwitch` does it) (`aef095d0`).
- CSS: the library stylesheet is one cascade layer `anzu-common` and brings Vuetify's reset in `vuetify-core.reset`. The admin must name `anzu-common` in its `@layer` statement between `vuetify-overrides` and `vuetify-utilities` and declare Vuetify's sub-layers right after it (statements in `doc/guide/installation.md`, checked by `describeCssLayerOrder`). Unlayered admin CSS now beats library CSS (`aef095d0`).
- Utility classes: `system-border-{t,b,l,r,a}` → Vuetify `border-t|b|s|e`/`border`; `line-clamp-1` → `text-truncate`; `line-clamp-2` → `a-line-clamp-2`; `required`/`required-mark` → `a-required-mark`; removed `system-border-x/y`, `line-clamp-3/4`, `cursor-pointer`, `white-space-pre`, `image-loading-effect`, `v-toolbar--custom-tiny` (`aef095d0`).
- `AChipNoLink` is registered by the plugin as the component (was a Vuetify alias of `VChip` in `commonAliases`) (`d1924b3b`).
- Tooltips on touch screens no longer open on hover/focus (`createAnzuVuetify` / `useCommonVuetifyConfig` defaults); the CSS rule that hid all tooltips there is commented out with a TODO (`aef095d0`).
- Fonts load through a `<link>`, `webfontloader` is gone (`aef095d0`).
- `socket.io-client` is not imported by the library: collaboration takes `io` from the admin in the plugin options (`collab.io`, type `CommonAdminCollabOptions`) (`4d86ae80`).

### 1.4 API helpers
- Labs helpers reworked: `executeRequest`/`executeFetch` → `execute`, `abortRequest`/`abortFetch` → `abort`, request body `object` → `body`; list helpers take the item type (`useApiFetchList<Author>` → `Promise<Author[]>`) (`b1a42ae5`).
- `useApiRequest<R, B>` requires a body in the answer (`R` cannot be `void`); body-less calls move to the new `useApiCommand<B>`; `optionalBody: true` for endpoints that answer either way. A body is detected by what arrived (`0`/`false` are bodies, `''`/`null` are not); a list needs an array, a 204 answers `[]` and resets pagination (`b1a42ae5`, `d0e99ce1`, `73cffc6c`, `f477283e`…`7cb0e6d5`).
- Type parameters order: `useApiRequest<Response, Body>` (old `apiCreateOne<Body, Response>`); a call that passed `{}` as body must keep passing it (`4d86ae80^:doc/changelog/unreleased/api-helpers-migration.md`, `b1a42ae5`).
- Failures arrive as `AnzuApiAxiosError` / `AnzuApiTimeoutError` / `AnzuApiResponseCodeError` / `AnzuApiCancelledError` (not always `AnzuFatalError`); all ten error classes extend `AnzuError`. Check `isAnzuApiAxiosError` branches that previously could not fire (`b1a42ae5`, `3301dc2a`).
- `silentConsoleError` (per instance) is replaced by `setApiErrorLogger(fn | null)`; 401/403, cancellations and mapped domain errors never reach it; `execute({ report: false })` throws without logging (`b1a42ae5`, `03c3a108`).
- `useApiFetchList` writes the pagination (`totalCount`, `hasNextPage`, `currentViewCount`) of its newest call only: two lists fetched at once need an instance each (`1552f10b` doc, behaviour from the api rework).
- Old one-shot helpers deleted: `apiFetchOne`, `apiCreateOne`, `apiUpdateOne`, `apiDeleteOne`, `apiFetchByIds`, `apiAnyRequest`, `apiFetchList`, `apiFetchListBatch`, `apiGenerateListQuery`, the `fetchDam*List` wrappers, `usePaginationAutoHide`; `useJobApi` is the labs one now (`3301dc2a`, `61dbabb2`, `1463ce82`). Replacements: `useApiRequest`, `useApiCommand`, `useApiFetchByIds`, `useApiFetchList`, `useApiFetchListBatch`, `useApiFetchItems`.

## 3. Changed behaviour
- Close (route history): one walk by name, never the current route; the remembered list page is kept only for the page Close lands on; Close between two details no longer ping-pongs; a list reopened by Close shows the page and rows-per-page it was left on, also with a non-default sort; the page is keyed per list (`9ac088d7`, `a3d3436d`, `97ecb8fe`, `cb718fc6`, `4130d1d9`, `79ce0df2`, `0dd5d838`, `fbeb7ff7`, `66d7e05a`).
- A detail/edit page that cannot load its record shows why and leaves to where the user came from (skips the record's own views, avoids back-and-forth loops, holds `loading`) (`adb579ec`); messages and redirects after async work only while the user is still on the page; a request aborted while waiting for the token refresh ends as cancelled (`845c0846`).
- URL filter hash: a hash naming a field is authoritative (other fields reset) and mirrored into local storage; a truncated hash no longer drops the sort; hash replaces the history entry and Back restores it (`a36be9c2`, `e73367fe`, `aef095d0`).
- Filter chips: no close button on a chip that has nothing to clear; a time interval pair keeps it when either half moved (`cbc3d63b`, `a8eec95c`).
- Filter bookmarks: Manage tab is a list editor — one Save for the tab, delete waits for Save, leaving asks first; new bookmark goes after the highest position; per-request results, newest answer wins (`0d818e7d`, `23a972fd`, `75fad86d`, `5e912066`, `bfe74dff`, `c74a09eb`).
- Token refresh: one "sign-in server is not responding" alert per outage (`common.alert.authUnavailable`) instead of system errors; the other tab's cookie is awaited after a 400 (`aef095d0`, `d1924b3b`).
- `Acl` re-evaluates when a system's current user arrives later or a permission is removed (`5ccfa5aa`); `canSafe` never throws (`0ea35fe2`).
- Cross-system user writes ask `UserSystemDescriptor.canWrite` first (`0ea35fe2`); a user/permission-group update answered after the page was left writes nothing into the store (`5fd29b08`).
- `defineCached` does not ask again on every `add()` for items it could not resolve; batches of 100; `useApiFetchByIds` batches of 100 (`d504b371`, `781e787d`).
- Unsaved-changes guard also asks when the path changes on the same route, and answers every waiting navigation (`fdea48d9`, `cb718fc6`).
