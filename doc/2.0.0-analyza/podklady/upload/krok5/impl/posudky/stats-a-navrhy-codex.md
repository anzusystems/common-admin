**Verdict: AGREE WITH CHANGE on 1 and 3; AGREE on 2.** The fixes address real issues, but the heartbeat needs pod identities, and the room-only scan must preserve the meaning of `connectedUsers`.

1. **AGREE WITH CHANGE — heartbeat registry.** The failure is real: the Redis Streams adapter counts current pub/sub subscribers, and `serverSideEmit` waits for that count minus one. A pod with live sockets but a lost subscription can therefore disappear from the expected replies and produce a partial 200 ([Redis Streams adapter](/home/volar/projects/petit/collaboration/node_modules/@socket.io/redis-streams-adapter/dist/adapter.js:226), [cluster adapter](/home/volar/projects/petit/collaboration/node_modules/socket.io-adapter/dist/cluster-adapter.js:415), [snapshot](/home/volar/projects/petit/collaboration/src/manager/collabStatsLiveManager.ts:78)). An independent heartbeat is justified if a 200 must mean complete counts. Have replies carry a unique process identity and compare *identities*, not just totals: a newly responding pod could otherwise mask a registered pod that missed the request. Scope keys by environment/version and register only ready pods. **Could go wrong:** expired heartbeats still leave a blind spot; delayed expiry or a stalled pod can cause temporary 503s. Reporting the number of responders is simpler, but it cannot establish that the counts are complete. A configured expected replica count is simpler only if that count is reliably fixed.

2. **AGREE — adapter membership events.** In the installed versions, `RemoteSocket.leave()` calls cluster `socketsLeave`; the receiving pod runs `delSockets` on its *local* sockets, which calls `socket.leave()`. Remote `disconnectSockets` likewise disconnects local sockets. Those paths reach adapter `leave-room`; normal disconnect calls `leaveAll()` before removing the socket from the namespace ([RemoteSocket](/home/volar/projects/petit/collaboration/node_modules/socket.io/dist/broadcast-operator.js:436), [cluster dispatch](/home/volar/projects/petit/collaboration/node_modules/socket.io-adapter/dist/cluster-adapter.js:114), [local removal](/home/volar/projects/petit/collaboration/node_modules/socket.io-adapter/dist/in-memory-adapter.js:235), [disconnect](/home/volar/projects/petit/collaboration/node_modules/socket.io/dist/socket.js:532)). The events provide `(room, socketId)`; the owning namespace’s `sockets` map still contains the socket and its `data` when they fire ([adapter events](/home/volar/projects/petit/collaboration/node_modules/socket.io-adapter/dist/in-memory-adapter.js:46), [namespace removal](/home/volar/projects/petit/collaboration/node_modules/socket.io/dist/namespace.js:286)). This also covers purge’s direct `RemoteSocket.leave()` path ([purge](/home/volar/projects/petit/collaboration/src/server/event/listener/purgeRoomListener.ts:39)). **Could go wrong:** a remote leave that never reaches its owner cannot trigger the event; filter to counted article rooms and keep existing `collabRooms` handling. The simpler alternative is to fix each leave path, but it is easier to miss another path.

3. **AGREE WITH CHANGE — room-based scan and responder cache.** Walking counted adapter rooms and looking up their local socket IDs avoids visiting every socket’s room set for each snapshot ([current scan](/home/volar/projects/petit/collaboration/src/util/helper/collabStatsRoomHelper.ts:27), [room membership map](/home/volar/projects/petit/collaboration/node_modules/socket.io-adapter/dist/in-memory-adapter.js:46)). A ≤5-second local responder cache is reasonable when several pods request snapshots. **Could go wrong:** `connectedUsers` currently includes users on *all* connected sockets, including those outside article rooms ([snapshot](/home/volar/projects/petit/collaboration/src/manager/collabStatsLiveManager.ts:81)); a room-only scan silently changes that field. Keep a separate all-socket pass for that field, or remove the field from the contract if the owner does not need it. The scan still visits all adapter room names, and responder caching can add staleness to the existing requester cache. Because the responder calculation is synchronous, a separate “single-flight” mechanism adds no practical value; a simple timestamped cache suffices.
