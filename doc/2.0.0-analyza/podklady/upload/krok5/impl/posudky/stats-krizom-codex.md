1. **Medium — a malformed cursor can leave a collaboration request unanswered.** In collaboration, [`decodeCursor()`](/home/volar/projects/petit/collaboration/src/manager/collabStatsHistoryManager.ts:149) calls `toISOString()` on a date that can be invalid. Parsing happens outside the response handler’s `try` block in [`collabStatsRequest.ts`](/home/volar/projects/petit/collaboration/src/server/document/collabStatsRequest.ts:57), and the HTTP hook discards the resulting promise in [`onRequestHook.ts`](/home/volar/projects/petit/collaboration/src/server/document/onRequestHook.ts:101). A token-authenticated request with a base64url cursor containing `s: "2026-13-01T00:00:00.000Z"` can therefore reject without the promised 400 response. Core-cms rejects that date before forwarding it in [`CollabStatsQueryFactory.php`](/home/volar/projects/petit/core-cms/src/Domain/CollabStats/Factory/CollabStatsQueryFactory.php:267). **Fix size: small**—make invalid dates return `null` and keep parsing inside the HTTP error boundary.

2. **Medium — a collaboration outage produces a core-cms warning on every live poll.** Admin-cms sends three requests every 10 seconds in [`collabStatsLive.ts`](/home/volar/projects/petit/admin-cms/src/domains/cms/collabStats/composables/collabStatsLive.ts:39). When collaboration is unreachable or times out, [`AnzuCollaborationClient.php`](/home/volar/projects/petit/core-cms/src/HttpClient/AnzuCollaborationClient.php:119) calls a helper that logs an unconditional warning at [line 164](/home/volar/projects/petit/core-cms/src/HttpClient/AnzuCollaborationClient.php:164). One open dashboard produces up to three warnings per poll, despite the exception class being excluded from normal app exception logging. **Fix size: small**—rate-limit or aggregate this client warning.

3. **Medium — collaboration still writes a log record for every repeated live failure.** The same three-request poll in [`collabStatsLive.ts`](/home/volar/projects/petit/admin-cms/src/domains/cms/collabStats/composables/collabStatsLive.ts:39) reaches [`logFailure()`](/home/volar/projects/petit/collaboration/src/server/document/collabStatsRequest.ts:43) when, for example, Redis or another collaboration instance is down. With info logging enabled, the outage still floods application logs; the warning interval only limits warnings and Sentry. **Fix size: small**—count suppressed failures in memory and log the aggregate at the interval.
