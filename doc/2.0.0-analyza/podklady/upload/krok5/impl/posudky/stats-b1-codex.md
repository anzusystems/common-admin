**Verdict: changes requested before B1 and B2 ship.** Commit `1edb565` implements the planned session, transaction, index, and separate Mongo connection structure, but I verified these failure paths in the committed code:

- **High — Stats can hold a room action after its answer.** [collabStatsSessionManager.ts](/home/volar/projects/petit/collaboration/src/manager/collabStatsSessionManager.ts:86) awaits the Lua call under the room lock; the shared Redis client has `maxRetriesPerRequest: null` in [redis.ts](/home/volar/projects/petit/collaboration/src/storage/redis.ts:12). If Redis stalls after a join or leave has answered, that action can remain pending until Redis recovers. The room lock’s 20-second limit then expires while the stats call is still outstanding. Catching a rejection does not bound this wait, so the hard “stats must not block collaboration” guarantee is unmet.

- **High — The hot-path Lua work grows with every past participant.** [collabStatsRedis.ts](/home/volar/projects/petit/collaboration/src/storage/collabStatsRedis.ts:104) runs `SMEMBERS` and visits every user ever recorded in the session on **each** membership event, including users long gone. A room kept open while many people rotate through it makes join, leave, kick, and purge progressively slower under the room lock; Lua also blocks other Redis work while it runs. The 50-person Mongo document cap does not bound this Redis work.

- **Medium — A committed session can later be counted as dropped.** Finalized markers expire after two days in [collabStats.model.ts](/home/volar/projects/petit/collaboration/src/mongoose/collabStats.model.ts:137), while session Redis keys last seven days. If Mongo commits and Redis cleanup cannot complete for over two days, the next finalizer run treats the retained session as older than the 24-hour pending limit in [collabStatsFinalizer.ts](/home/volar/projects/petit/collaboration/src/manager/collabStatsFinalizer.ts:332). Its marker has expired, so [the dropped write](/home/volar/projects/petit/collaboration/src/manager/collabStatsFinalizer.ts:199) increments `collab_daily.dropped` for a session already written. The marker protects the normal commit-to-cleanup crash window, but not this one.

- **Medium — The document cap does not cover collaboration pairs.** [collabStatsSessionHelper.ts](/home/volar/projects/petit/collaboration/src/util/helper/collabStatsSessionHelper.ts:147) constructs a pair for every qualifying editor combination, even though only 50 participants are retained in the document. [fitDocument](/home/volar/projects/petit/collaboration/src/util/helper/collabStatsSessionHelper.ts:192) trims only `fieldsChanged`. A long session with many editors in the same five-minute window can therefore exceed the stated 256 KB cap and make finalization increasingly expensive; sufficiently large documents fail Mongo insertion.

The code has the requested named indexes, `_id` cursor suffixes, 30-day TTL indexes, dedicated pool of three with buffering and debug disabled, Redis mutex, and `COLLAB_STATS_ENABLED=false` gates for session writes, queue, and stats Mongo connection. The real-Lua parity test is [conditional on `REDIS_TEST_URL`](/home/volar/projects/petit/collaboration/test/collabStatsMembership.test.ts:305), so ordinary test runs do not prove parity.
