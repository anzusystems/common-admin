The best measured change is the awareness fast path. The remaining stats and lock ideas are **hypotheses**: the measurements identify regressions, but do not isolate those changes’ gains. All recommendations below are for a later implementation and measurement; I made no changes or runs.

1. **Skip Hocuspocus’s scratch document when no awareness hook is installed.** Change the awareness branch in [MessageReceiver.ts](/home/volar/projects/petit/collaboration/node_modules/@hocuspocus/server/src/MessageReceiver.ts:88), with hook detection in [Hocuspocus.ts](/home/volar/projects/petit/collaboration/node_modules/@hocuspocus/server/src/Hocuspocus.ts:467). The server’s configured extensions in [hocuspocus.ts](/home/volar/projects/petit/collaboration/src/server/hocuspocus.ts:23) have no such hook. Directly applying the update avoids creating a `Y.Doc` and `Awareness`, decoding, and encoding again for each cursor message. **Measured gain:** two prototype comparisons cut CPU by **2.77–3.12 percentage points** and edit p99 by **2.69–5.03 ms** ([COLLAB-PERF §3](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/COLLAB-PERF.md:140)). Those trials preceded the final H3/H4 build, so their gain on the current build is an extrapolation. **Risk:** silently bypassing a future hook could change or fail to reject awareness updates; keep the hook path as fallback. **Size:** medium, preferably upstream rather than a lasting dependency patch. **Measure:** paired `b1-awarefast`/`b1-tuned` style runs on the current build, then scenario `d`; compare CPU, edit p99, GC, and awareness delivery.

2. **Try disabling Hocuspocus WebSocket compression.** Set `perMessageDeflate: false` in [hocuspocus.ts](/home/volar/projects/petit/collaboration/src/server/hocuspocus.ts:46). **Hypothesis:** remove zlib work and contention with the main thread. The rotation [CPU profile](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/STATS-PERF.md:172) attributes roughly **5% of one core** to this compression; there is no compression-off A/B result, so 5 points is a cost indication, **not** a promised saving. **Risk:** more network traffic, potentially slower clients or Redis-linked broadcasts where bandwidth matters. **Size:** tiny. **Measure:** paired compression on/off `b`, `d`, and `rot` runs with the heap and lock settings held fixed; compare CPU, edit latency, bytes sent, and delivery.

3. **Avoid a cluster-wide socket lookup when the field writer’s own socket is already in the room.** In [changeFieldDataListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/changeFieldDataListener.ts:46), check `socket.rooms.has(room)` first and call `hasNotUserId()` only when it is false. This preserves the current allowance for a user’s *other* socket. **Hypothesis:** remove one `fetchSockets()` and its adapter `PUBSUB NUMSUB` path from common field writes. The [adapter analysis](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/COLLAB-PERF.md:128) counted **435 NUMSUB/s** in scenario `c`, alongside **12% higher CPU** than 1.14.1; it did not isolate this lookup. **Risk:** a stale local room membership could authorize a write briefly after a remote removal; verify socket.io’s local membership timing. **Size:** small. **Measure:** paired `c` runs, plus `d` for cross-pod behavior; inspect NUMSUB/s, field-change ack p99, throughput, and refused writes.

4. **Move only the `occupied` statistics counter onto the existing B2 flush path.** Replace the awaited membership call at [joinCollabRoomListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/joinCollabRoomListener.ts:95) with `recordRequest`, extending its counter type in [collabStatsEditManager.ts](/home/volar/projects/petit/collaboration/src/manager/collabStatsEditManager.ts:14). An occupied response changes no room membership, while its current [Lua path](/home/volar/projects/petit/collaboration/src/storage/collabStatsRedis.ts:204) runs under the room lock. **Hypothesis:** fewer short lock holds in rotation; the measured run had **1,245 occupied responses**, and M2 still shows join/leave p99 penalties of **+2.8/+16 ms** ([M2 table](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/STATS-PERF.md:334)). Those penalties cannot be assigned specifically to occupied calls. **Risk:** a delayed flush could attribute an occupied count to a successor session or lose it on failure; preserve session attribution and existing incomplete markers. **Size:** small to medium. **Measure:** paired `hl-stats-rot` off/on variants; compare Redis commands, join/leave p99, and the tool’s session-counter checks.

5. **Isolate room-lock Redis traffic from other collaboration commands.** Give Redlock in [exectionLockHelper.ts](/home/volar/projects/petit/collaboration/src/util/helper/exectionLockHelper.ts:35) its own managed Redis connection, without changing its retry policy. **Hypothesis:** frequent contenders stop queuing behind the lock holder’s ordinary Redis commands. With heap fixed, the isolated M1 `c` comparison changed field-change p99 from **8.9 to 24.0 ms**, while CPU stayed **30.6–30.7%** ([M1 analysis](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/STATS-PERF.md:322)); command-queue interference is inferred, not profiled. **Risk:** another connection per pod, changed command ordering, and different behavior during Redis reconnects. **Size:** small. **Measure:** repeat `m1-c-heap400` with only connection isolation varied; check field-change p99, lock failures, Redis commands, and `rot` join/leave p99.

6. **If edit latency matters more than batching, set Hocuspocus `flushDelay: false`.** Add it at [hocuspocus.ts](/home/volar/projects/petit/collaboration/src/server/hocuspocus.ts:39). **Measured gain:** the `b0-noflush` trial improved edit p50 by **0.52 ms** and p99 by **1.52 ms**, with no meaningful CPU gain ([COLLAB-PERF §3](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/impl/COLLAB-PERF.md:140)). **Risk:** more individual broadcasts and potentially worse CPU or network use at higher edit rates. **Size:** one option. **Measure:** paired `b` and `d` runs, including broadcast counts and cross-instance p99.
