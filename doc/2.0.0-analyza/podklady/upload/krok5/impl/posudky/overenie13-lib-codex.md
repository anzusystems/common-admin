### Claim 232 — PARTLY

In an article with **two editors**, open the Supplementary media listing image’s library or metadata dialog, then pin that widget without confirming. Pinning removes its original component and draws a copy in the sidebar ([pin toggle](/home/volar/projects/petit/admin-cms/src/domains/cms/article/components/widgets/ArticleWidgetPinnable.vue:61), [sidebar copy](/home/volar/projects/petit/admin-cms/src/domains/cms/article/components/ArticleEditForm.vue:525)). The original widget’s `onBeforeUnmount` only marks it disposed and cancels waits; it does **not** release the lock, and the widget has no `onUnmounted` release ([image](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageWidgetInner.vue:299), [media](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageMediaWidgetInner.vue:310)). No image text is written wrong by the unmount itself. **Smallest fix: M** — release on unmount when no save or delete is pending and no later lock turn owns the field; keep the existing save completion release. The field becomes available promptly. Risk: releasing a replacement copy’s lock too early or sending a second release.

### Claim 233 — PARTLY

With **two editors** and a slow image update, edit the Supplementary media listing image, change its text, press “Potvrdiť,” then pin the widget before the response. If the new copy’s image fetch returns **before the update takes effect**, it caches the old text ([reload](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageWidgetInner.vue:444)). The disposed original does not apply or reload its save response ([save response](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageWidgetInner.vue:683)). Opening “Upraviť metadáta” copies the cached text into the form; confirming updates the same image ID with those old fields ([edit](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageWidgetInner.vue:279), [update](/home/volar/projects/anzusystems/common-admin/src/domains/dam/imageWidget/components/ImageWidgetInner.vue:683)). The newly saved text is overwritten, and the other editor can then read the reverted image. A copy whose fetch returns after the update gets the new text, so pinning during the request alone does not prove the loss.

**Smallest fix: M** — fetch the current image before opening metadata editing, and reject or refresh the form if it changes before confirmation. The editor may briefly see loading, then current text. Risk: a failed refresh could prevent the dialog from opening.
