## Claim 228: PARTLY

Both reads can return a main file marked `processed`, and neither passes that result to the open detail. The lasting “Save” problem needs a qualification: when the user has already edited the form, a quiet read deliberately keeps Save blocked even after it learns the file is processed.

**(a) Mass edit — HOLDS.** Selecting a list row calls `addByAssets`, which starts `fetchLazyAdditionalMetadata` ([selection](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/list/composables/assetListActions.ts:398), [batch request](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/uploadQueuesStore.ts:498)). Its `/ids/` response contains detail DTOs ([backend endpoint](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Controller/Api/Adm/V1/AssetController.php:139), [DTO mapping](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Repository/Decorator/AssetAdmRepositoryDecorator.php:42)), including `mainFile.fileAttributes.status` ([main file](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Model/Dto/Asset/AssetAdmListDto.php:55), [status](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Model/Dto/AssetFile/Embeds/AssetFileAttributesAdmDto.php:16)). The result updates mass edit rows, not the detail ([row writes](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/uploadQueuesStore.ts:518)). The mass edit role has no reader or poll ([policy](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/uploadQueuesStore.ts:103)).

An ordinary sequence is: open an undescribed asset in the list’s side panel while its file is processing; after processing completes, select that row for mass edit. The batch can receive `processed` while the panel still holds the earlier status. If the processed notification arrives, it tells the detail; the mass edit row itself will not poll it.

**(b) Asset list — HOLDS.** Refreshing the list requests list DTOs and writes them only to the list store ([request and write](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/list/composables/assetListActions.ts:158), [store](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/assetListStore.ts:74)). The backend’s list DTO includes the same main file and status fields ([list DTO](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Model/Dto/Asset/AssetAdmListDto.php:55), [status](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Model/Dto/AssetFile/Embeds/AssetFileAttributesAdmDto.php:16)). With that panel still open, the user can press the list refresh button ([button](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/list/AssetListView.vue:211)); a returned `processed` row does not update the panel. A normal list refresh has no queue poll. A delivered notification does update it ([listener](/home/volar/projects/anzusystems/admin-dam/src/domains/system/composables/appNotificationListeners.ts:32)).

**What is lost.** With an untouched form, these omissions mean waiting for a notification; if that notification is missed and no queue read covers the asset, Save can remain blocked until the detail is reopened. With edits already typed, even a notification’s quiet read intentionally retains the Save block to avoid saving a form older than server filled metadata ([quiet read](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/composables/assetDetailFileChange.ts:60), [save gate](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/AssetDetailSidebarMetadata.vue:51)). Calling `mainFileProcessed` cannot free that edited form by itself.

**Smallest fix: S.** On each accepted read, check for the currently held asset and a matching main file with `processed` status, then call [`mainFileProcessed`](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/assetDetailStore.ts:201). An untouched detail would refresh quietly and release Save sooner. Match the asset and file IDs before calling; notification and read races may otherwise start an extra quiet request. The store’s ID check prevents a read of another asset.
