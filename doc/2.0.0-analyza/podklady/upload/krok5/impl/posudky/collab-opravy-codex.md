**High — X1 still lets any authenticated user purge an arbitrary room.** The check accepts membership in `${room}:info` ([purgeRoomListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/purgeRoomListener.ts:15)), but `subscribeCollabRoomInfo` joins that channel without a room or role check ([subscribeCollabRoomInfoListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/subscribeCollabRoomInfoListener.ts:10)). **Medium — H5 can be cut short during a slow store.** Shutdown calls `hocuspocusServer.destroy()` ([index.ts](/home/volar/projects/petit/collaboration/src/index.ts:61)), which closes clients and flushes pending stores ([hocuspocus-server.esm.js](/home/volar/projects/petit/collaboration/node_modules/@hocuspocus/server/dist/hocuspocus-server.esm.js:1745)). `Graceful` still has its default 5-second deadline and calls `process.exit(1)` when it expires ([graceful/index.js](/home/volar/projects/petit/collaboration/node_modules/@ladjs/graceful/index.js:20), [graceful/index.js](/home/volar/projects/petit/collaboration/node_modules/@ladjs/graceful/index.js:267)). The shutdown test uses short mocked operations ([index.test.ts](/home/volar/projects/petit/collaboration/test/index.test.ts:3)).

**Medium — X1’s lock can expire before purge finishes.** `purgeRoom` uses the default room-lock duration ([purgeRoomListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/purgeRoomListener.ts:24)); that duration is 1,000 ms, with no extension in this listener ([exectionLockHelper.ts](/home/volar/projects/petit/collaboration/src/util/helper/exectionLockHelper.ts:25)). Purging storage, fetching room information and fetching sockets all run before kicking users ([purgeRoomListener.ts](/home/volar/projects/petit/collaboration/src/server/event/listener/purgeRoomListener.ts:27)). If those operations exceed one second, another room action can acquire the lock while the purge is still running; a joining editor can enter a room whose state is then cleared or whose socket is kicked. The test’s mocked lock has no expiry ([purgeRoomListener.test.ts](/home/volar/projects/petit/collaboration/test/purgeRoomListener.test.ts:43)).

**Low — H5 does not close Sentry last.** Its handler waits for the custom handlers, then calls `Sentry.close()` ([index.ts](/home/volar/projects/petit/collaboration/src/index.ts:65)); `Graceful` closes Redis and Mongo only afterward ([graceful/index.js](/home/volar/projects/petit/collaboration/node_modules/@ladjs/graceful/index.js:283)). If either database close logs an error, operators may lose that Sentry event. Repeated signals are guarded by `Graceful`’s `_isExiting` flag ([graceful/index.js](/home/volar/projects/petit/collaboration/node_modules/@ladjs/graceful/index.js:256)).
