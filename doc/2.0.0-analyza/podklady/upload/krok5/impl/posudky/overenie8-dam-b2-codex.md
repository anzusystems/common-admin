## FE-68 — “Make public” dialog

**Verdict: HOLDS.**

**Steps.** Open an audio or document file’s Info card, open its route menu, click **Make public**, change the slug, and click **Confirm** when the request will be refused. The error alert appears and the dialog closes. Reopening it replaces the typed slug with one generated from the title. For a processed file, entering `ab!` passes the field’s three-character check but sends `ab`; entering only Cyrillic letters sends an empty slug.

**Evidence.** The dialog [validates `slug` but sends `stringToSlug(slug)`](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/shared/assetFileRoute/components/AssetFileRouteMakePublicDialog.vue:54), using a conversion that [removes characters outside ASCII word characters and hyphens](/home/volar/projects/anzusystems/common-admin/src/shared/utils/string.ts:79). Audio and document requests put that result in the JSON `slug` ([audio request](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/api/audioApi.ts:124)); the backend requires [3–128 characters and a restricted pattern](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Model/Dto/AssetFileRoute/AssetFileRouteAdmCreateDto.php:13). The dialog [calls `onCancel()` in `finally`](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/shared/assetFileRoute/components/AssetFileRouteMakePublicDialog.vue:85), including after rejection, and [regenerates the slug on reopening](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/shared/assetFileRoute/components/AssetFileRouteMakePublicDialog.vue:46). The route API propagates the raw Axios error; [the alert handler does not recognize that as a mapped validation error](/home/volar/projects/anzusystems/common-admin/src/domains/system/composables/alerts.ts:130), so this path shows the generic error.

**Fix.** Close only after success; validate the converted slug against the backend’s length and pattern before sending, with the error attached to the field. This preserves the typed value for another attempt and prevents these invalid requests. Converting the field on every keystroke would visibly rewrite what the user types and disrupt editing; keep conversion at validation/submission. Image publication has no slug field and must remain exempt.

**Existing test.** [“is not read after a ‘Make public’ the server refused…”](/home/volar/projects/anzusystems/admin-dam/src/test/list/mainRouteChange.test.ts:445) already exercises refusal and explicitly expects the dialog to close. It does not cover slug conversion.

## Q7 — “Make public” during processing

**Verdict: HOLDS.**

**Steps.** With file-update permission, open an asset whose image, audio, or document main file exists but is still `uploaded` or `stored`. In its Info card or Slots tab, open the file’s route menu and choose **Make public**; confirm the dialog for audio or document. The action is offered, but the backend refuses it. The same menu can be reached for other nonprocessed states when such a file is displayed.

**Evidence.** The shared menu [offers Make public when there is no route and the user can update the file](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/shared/assetFileRoute/components/AssetFileMainRoute.vue:74), without a status check. It is used by the [Info file card](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/AssetMetadata.vue:264) and [slot rows](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/slots/AssetSlotListItem.vue:174). The status is available as `assetFile.fileAttributes.status` in both places ([slot row](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/slots/AssetSlotListItem.vue:79)).

For **both** [image `makeImagePublic`](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Domain/AssetFileRoute/AssetFileRouteFacade.php:47) and [audio/document `makePublicFromDto`](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Domain/AssetFileRoute/AssetFileRouteFacade.php:61), only `processed` passes the [state guard](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Domain/AssetFileRoute/AssetFileRouteFacade.php:149). `uploading`, `uploaded`, `stored`, `duplicate`, and `failed` are refused. For a valid DTO, each nonprocessed request gets **HTTP 422** with `error: "forbidden_operation_error"`, `detail: "forbidden_operation_error"`, and a `contextId` ([handler](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Exception/Handler/ForbiddenOperationExceptionHandler.php:19)). That detail gives no processing-specific reason. An invalid audio/document slug can instead fail DTO validation first. The admin’s raw Axios error path shows a generic alert as described in FE-68.

**Fix.** Hide **Make public** until `processed`, and hide the otherwise empty route menu when the file has no route. That fits the menu’s existing conditional rendering; disabling the item without explanatory text would leave a dead-looking action. This visibly removes publication during processing. Apply the condition only to Make public: **Make private** and Copy URL must stay available for a file that already has a route, since [Make private checks route existence, not process status](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Domain/AssetFileRoute/AssetFileRouteFacade.php:75). Gating the whole menu by status would break those paths.

**Existing test.** No test found for the processing-state guard in the menu. [The list route-change test](/home/volar/projects/anzusystems/admin-dam/src/test/list/mainRouteChange.test.ts:651) uses a `stored` file in a different scenario; it does not verify this refusal.

## FE-69 — detail refresh and Slots tab

**Verdict: PARTLY.** The discarded edits and stale Info card are proved. The claimed result of clicking every stale public URL depends on how that URL is served.

**Steps.** Open a standalone asset page at `/assets/<id>` or its file page at `/assets/file/<id>`. Type metadata without saving, then use the Info card’s **Make public** or **Make private** action. On success, the page loads the whole asset again and the typed values disappear without a question. Separately, on an asset with a public main file, open **Slots**, make that slot private, then return to **Info**: its file card still shows the old public route. Or choose **Make main file** on another slot and return to Info: it still shows the previous main file.

**Evidence.** Both standalone pages wire `main-route-changed` to `getDetail` ([asset page](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/AssetDetailView.vue:233), [file page](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/AssetFileDetailView.vue:210)); their successful reads call `setAsset` ([asset page](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/AssetDetailView.vue:97), [file page](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/AssetFileDetailView.vue:90)). That [clears `metadataAreTouched` and replaces the asset](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/store/assetDetailStore.ts:118). The list page already [takes only `mainFile.mainRoute` when metadata was touched](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/list/composables/assetListActions.ts:310).

In Slots, a route change [emits only `refreshList`](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/slots/AssetSlotListItem.vue:174), which [rereads the slot list](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/slots/AssetDetailSidebarSlots.vue:92). **Make main file** likewise [rereads only slots](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/composables/assetDetailSidebarSlotsActions.ts:52). The Info card reads the separate detail-store `asset.mainFile` ([card](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/AssetMetadata.vue:255)). For a route served by the backend route controller, a removed route returns [404](/home/volar/projects/petit/core-dam/vendor/anzusystems/core-dam-bundle/src/Controller/AssetFileRouteController.php:42); the code does not prove that every public URL uses that delivery path.

**Fix.** Use the list’s route-only update on both standalone pages **when metadata is touched**; keep a guarded full refresh when it is not. Propagate a successful Slots route change for the **main file** to the same refresh path. This preserves typed metadata and updates Info. The proposed route event alone does **not** fix **Make main file**: that action needs to update or reread `mainFile` while preserving touched metadata and related form state. Applying a route-only update to that action would leave the old file in Info; applying an unconditional full refresh would repeat the edit-loss defect.

**Existing test.** [mainRouteChange.test.ts](/home/volar/projects/anzusystems/admin-dam/src/test/list/mainRouteChange.test.ts:648) covers the list’s route-only rule. [assetSlotActions.spec.ts](/home/volar/projects/anzusystems/admin-dam/e2e/tests/assets/assetSlotActions.spec.ts:78) checks the changed main file in the API and Slots, but not the still-open Info card. No exact standalone-page or cross-tab test found.

## FE-71 — loader arrows and provider counter

**Verdict: PARTLY.** Clicks on the loader arrows are lost. The provider counter is wrong **after a DAM list visit**; on a fresh provider visit it is blank.

For the counter, first open a DAM list asset, navigate to an external provider list, open a provider asset, and step to another while its detail loads. The loader can show the retained DAM index and total instead of the provider’s. Opening the provider first leaves that loader counter empty.

**Evidence.** The loaded DAM detail [emits navigation clicks and disables arrows at the ends](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/AssetDetailDialog.vue:186), but it is replaced during loading by [AssetDetailDialogLoader](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/AssetDetailDialog.vue:170), whose arrow handlers are [empty and whose buttons lack end guards](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/components/detail/components/AssetDetailDialogLoader.vue:43).
