1. **A repeated client ID can escape disconnect cleanup.** [MessageReceiver.ts:87](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/src/MessageReceiver.ts:87) now applies every entry directly. In [y-protocols/awareness.js:249](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/node_modules/y-protocols/awareness.js:249), one update containing a removal for client C followed by a newer live state for C emits both `removed` and `updated`. [Document.ts:272](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/src/Document.ts:272) then deletes C from the connection’s tracked clients; [Document.ts:186](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/src/Document.ts:186) cannot remove C on disconnect. The scratch path collapses those entries to the final live state before applying them. The final awareness state initially matches, but `update`/`change` payloads and cleanup differ. A crafted multi-entry frame can leave a departed client visible until awareness timeout. The new provider tests send ordinary updates and do not cover this case.

2. **A malformed frame can leave an unannounced ghost state.** [MessageReceiver.ts:87](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/src/MessageReceiver.ts:87) applies directly; [y-protocols/awareness.js:249](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/node_modules/y-protocols/awareness.js:249) mutates entries as it decodes and emits events only after the whole loop. If a valid new-client entry precedes a truncated entry, decoding throws after changing `states` and `meta`, without an `update` event. Consequently [Document.ts:268](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/hocuspocus/packages/server/src/Document.ts:268) never tracks that client for disconnect cleanup; a later connection can receive the ghost state. [PR.md:64](/home/volar/projects/anzusystems/krok5-praca/hocuspocus-pr/PR.md:64) admits partial application but understates this consequence. The scratch path leaves the target untouched.
