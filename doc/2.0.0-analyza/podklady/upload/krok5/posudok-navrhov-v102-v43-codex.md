## Core design — findings

- **WRONG** — [PV16, line 1515](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/navrh-jadro.md:1515) says the proposed `report` flag would reduce Sentry reports to one per outage. It controls the API helper’s logger, which defaults to `console.error` ([apiErrors.ts:70](/home/volar/projects/anzusystems/common-admin/src/domains/api/utils/apiErrors.ts:70)). When Sentry is enabled, admin-dam’s HTTP integration independently captures each 5xx response ([main.ts:77](/home/volar/projects/anzusystems/admin-dam/src/main.ts:77), [httpclient.js:6](/home/volar/projects/anzusystems/admin-dam/node_modules/@sentry/browser/build/npm/esm/dev/integrations/httpclient.js:6)). `report: false` would not suppress those events.

- **MISLEADING** — [PV16, line 1515](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/navrh-jadro.md:1515) presents 15, 30, 60, 120, then 300 seconds as the failure cadence. Those are minimum delays: the actual delay is the maximum of that value and the normal polling delay ([distributionListPoll.ts:42](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/composables/distributionListPoll.ts:42)). For example, after five minutes the first failure waits 60 seconds, not 15; polling also pauses while the tab is hidden ([distributionListPoll.ts:81](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/composables/distributionListPoll.ts:81)).

- **GAP** — [PV16, line 1515](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/krok5/navrh-jadro.md:1515) proposes sending `report: failures === 0`, but `failures` is private to the poller and its read callback receives only a signal ([distributionListPoll.ts:56](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/composables/distributionListPoll.ts:56), [distributionListPoll.ts:69](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/composables/distributionListPoll.ts:69)). The distribution API wrapper also has no `report` parameter ([distributionApi.ts:42](/home/volar/projects/anzusystems/admin-dam/src/domains/coreDam/asset/api/distributionApi.ts:42)). The design needs to specify how that state and option reach the helper.
