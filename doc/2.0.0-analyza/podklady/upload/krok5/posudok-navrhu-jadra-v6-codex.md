## Findings

- **WRONG — Z9 / PV5:** The promised full ring and disappearance of the remaining time are conditional on a speed sample. With no sample, the LIB meter sends no final progress callback, so the stated visible change does not occur. The register notes the condition, but its “what a user notices” cell and PV5 omit it. - **WRONG — Z25:** “Both hooks clear the error” conflates two cases. The processed-file hook clears a mass edit row’s file error; the metadata hook clears only a recorded *missing-metadata* error. A metadata notification does not restore the form of a row whose file failed. - **GAP — Z25 / PV9:** The owner facing text leaves “Refresh” as an open question, but the current path answers it: Refresh reads with `early: false`; a mass edit row has `settleOn: 'never'`, and its metadata is loaded on this path only for an early read. Thus, if F3 changes only `Failed` to `Uploaded`, the button can appear after 20 seconds yet leave the form locked and the row excluded from bulk save.
