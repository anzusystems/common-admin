## Design errors and corrections

1. **Mass edit recovery is unreachable as drawn.** The `metadata`/`never` cell says “nothing” ([design:347](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:347)); the `applyAssetRead` pseudocode also exits on `settleOn: never` before its stated metadata gate ([design:271](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:271)). DAM currently recovers a bulk load miss on a metadata notification (`asset/store/uploadQueuesStore.ts:618-645`). Let that event name the asset even for `never`, run `metadataGate` before `decorate`, and preserve its warning cleanup.

2. **`afterDecorate` clears mass edit errors on the wrong trigger, and sometimes not at all.** The hook is specified for any decoration ([design:729](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:729)), whereas today only a `processed` event clears the error (`DAM asset/store/uploadQueuesStore.ts:514-532`). Conversely, today it clears before an asset fetch, even if `mainFile` is absent; the proposed read path exits first ([design:271](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:271)). Put the error action on the matching `processed` event, independent of decoration.

3. **Named reads bypass the poller’s serialization.** Notifications use a separate `named` map and reader path ([design:238](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:238), [349](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:349)); only `QueuePoller.runRead` guards `inFlight` ([design:486](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:486)). A named read and tick can therefore overlap for the same queue, violating plan §3.2’s one read at a time. Route both through one queue read coordinator while keeping notification reads limited to named assets.

4. **Read sequence does not order events.** DAM writes `processed` immediately (`asset/store/uploadQueuesStore.ts:514-535`). A poll sent before that event can return `failed` afterward; `lastAppliedSeq` compares reads only ([design:533](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:533)). Stamp event transitions too and reject pre-event responses. Check row/queue validity after every awaited origin, asset, or slot read.

5. **A new row can lose its earlier deadline during an active read.** `rowAdded()` moves `nextAt` forward, but successful `runRead` assigns a fresh `nextAt` ([design:491](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:491), [496](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:496)). Preserve the earlier pending deadline or queue a follow-up when the new row becomes due, as plan §3.2 requires.

6. **DAM manual refresh is not row-specific in the proposed wiring.** `refreshQueueItem` passes `fileId: null` ([design:749](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:749)); DAM’s matcher treats null as a match for any nonslot file of that asset (`asset/store/uploadQueuesStore.ts:492-508`). Pass the clicked row’s `fileId`, and handle slot refresh through its slot reader if exposed.

7. **Configuration accepts values outside the owner’s decision.** Plan §3.1 enables push for boolean `true` or string `"true"` (`upload-plan.md:84-90`); the design also accepts `" TRUE "` ([design:859](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:859)). Use the exact approved values. This is a product configuration change otherwise.

8. **The design contradicts itself on the manual gap and missing enrichment.** Its poller applies `MIN_GAP` to `readNow` ([design:500](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:500)), while O14 says not to; §3.8 says `awaitingRead` simply stops after three misses ([design:359](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:359)), while O12 says to show R7. Resolve both as above before implementing. The stated N-S1–N-S14 gate also lists cases only through N-S10 ([design:929](/home/volar/projects/anzusystems/common-admin/doc/2.0.0-analyza/podklady/upload/noc/navrh-krok2.md:929)); define the missing cases or correct the gate.
