# i18n

## For product owner/translators
- you can find translations in `src/locales/[lang]` in common-admin and all admins too
- if you need a new language to use in admin, it must be added to common admin first (see [adding a language](#adding-a-language))

## For developer
- admin creates its own vue-i18n instance (`createI18n` in `@/plugins/i18n`, with `slovakPluralizationRule` from common-admin, see [pluralization](#pluralization))
- the admin passes that instance to the plugin (`i18n` option): common-admin translates its components, validators and alerts through it, so there is one instance and one copy of the messages
- language translations are lazy loaded on app load

<details>
<summary>Example - admin i18n instance</summary>

```ts
// src/plugins/i18n.ts
import { createI18n } from 'vue-i18n'
import type { Locale, Path } from 'vue-i18n'
import { slovakPluralizationRule, type LanguageCode } from '@anzusystems/common-admin'
import type sk from '@/locales/sk'

export type MessageSchema = typeof sk

export const DEFAULT_LANGUAGE: LanguageCode = 'sk'
export const AVAILABLE_LANGUAGES: Array<LanguageCode> = ['sk', 'en']

const REQUIRED_LOCALES = ['sk']

export const i18n = createI18n<[MessageSchema], LanguageCode, false>({
  globalInjection: false,
  legacy: false,
  locale: 'sk',
  fallbackLocale: false,
  pluralRules: {
    sk: slovakPluralizationRule,
  },
  missing: (locale: Locale, key: Path) => {
    if (REQUIRED_LOCALES.includes(locale)) {
      console.warn(`Missing ${locale} translation: ${key}`)
    }
  },
})
```

- `legacy: false` is required, legacy mode ignores `pluralRules`
- `globalInjection: false`: there is no `$t` in templates, use `const { t } = useI18n()`
- missing keys are displayed as keys (`fallbackLocale: false`), `missing` warns only for `REQUIRED_LOCALES`

</details>

- keys are typed from the Slovak messages (`MessageSchema` above), declared in a `.d.ts` (e.g. `src/plugins.d.ts`):

```ts
import type { MessageSchema } from '@/plugins/i18n'

declare module 'vue-i18n' {
  export interface DefineLocaleMessage extends MessageSchema {}
}
```

<details>
<summary>Example - loading translation texts by using vue-router on first load</summary>

```ts
// src/loadLanguageMessages.ts
import { type LanguageCode, modifyLanguageSettings } from '@anzusystems/common-admin'
import { AVAILABLE_LANGUAGES, DEFAULT_LANGUAGE, i18n } from '@/plugins/i18n'
import { ref } from 'vue'

export const initLanguageMessagesLoaded = ref(false)

const { initializeLanguage, addMessages, currentLanguageCode } = modifyLanguageSettings(
  AVAILABLE_LANGUAGES,
  DEFAULT_LANGUAGE,
  i18n
)

export const initLoadLanguageMessages = async () => {
  const loadMessages = async (code: LanguageCode | 'default') => {
    if (code === 'default' || code === 'xx') {
      initLanguageMessagesLoaded.value = true
      return true
    }
    try {
      const messages = await import(`./locales/${code}.ts`)
      addMessages(code, messages.default)
      initLanguageMessagesLoaded.value = true
      return true
    } catch (e) {
      console.error('Unable to load language translation messages.', e)
      return false
    }
  }
  initializeLanguage()
  await loadMessages(currentLanguageCode.value)
}
```

```ts
vueRouter.beforeEach(async () => {
  if (!initLanguageMessagesLoaded.value) await initLoadLanguageMessages()
})
```

</details>

<summary>Example - switching language</summary>

`ALanguageSelect` stores the selected language, emits `afterChange` and the admin reloads, so messages are loaded on app load again. Until then the page keeps the current language: a language switches only once its messages are loaded (`addMessages`). `currentLanguageCode` is the chosen language, so until the reload it can be ahead of the one displayed.
```vue
<script lang="ts" setup>
import { ALanguageSelect } from '@anzusystems/common-admin'

const afterLanguageChange = () => {
  window.location.reload()
}
</script>

<template>
  <ALanguageSelect
    :is-administrator="isSuperAdmin"
    @after-change="afterLanguageChange"
  />
</template>
```

</details>

- common admin must contain translation for all languages used in admins
- language `xx` is used as system language for development purposes to display translation keys for admin user; `ALanguageSelect` offers it only with `is-administrator`, and it needs no messages (the loader skips it)
- translations are merged to this object:

```ts
export default {
  common: {
    component1,
    component2,
    entity1,
    entity2,
    // and more
  },
  $vuetify: vuetify,
  error: {
    apiValidation: {
      ...apiValidation,
    },
    apiForbiddenOperation: {
      ...apiForbiddenOperation,
    },
    apiDependencyExists: {
      ...apiDependencyExists,
    },
    jsValidation: {
      ...jsValidation,
    },
    apiTimedOut: {
      ...apiTimedOut,
    },
  },
}
```

#### error
- errors consist of `apiValidation`, `apiForbiddenOperation`, `apiDependencyExists`, `jsValidation` and `apiTimedOut`
- `apiValidation`: anzu API can return validation error response with specific format containing keys that needs to be translated for user
- `apiForbiddenOperation`: same as above but for forbidden error response
- `apiDependencyExists`: message for dependency exists error response
- `jsValidation`: custom validation texts used by vuelidate and js validation inside vue app
- `apiTimedOut`: message for timed out API request

#### $vuetify
- custom modified translations for vuetify components
- vuetify reads them through the admin's `i18n` (`createAnzuVuetify({ i18n })` sets up `createVueI18nAdapter`, see [installation](installation.md#vuetify)), so every admin language file keeps `$vuetify: messagesSk.$vuetify`

#### common
- all translations used by common admin components or really commonly reused translation are all prefixed by `common.xxx...`
> [!WARNING]
> Do not add new root object keys to translations, put all new translation in `common` key so its clear it's for common admin. If you really need it, consult it with team and update docs.

- translation texts are then exported for each language, so you can import only needed languages in admin
- in admin, you need to merge some translation, so it will contain messages used by common admin and admin messages, example:
```ts
import { messagesSk } from '@anzusystems/common-admin'

export default {
  common: messagesSk.common,
  $vuetify: messagesSk.$vuetify,
  cms: {
    site,
    job,
    article,
    rubric,
    // and more
  },
  sidebar,
  breadcrumb,
  system,
  error: {
    ...messagesSk.error,
    apiValidation: {
      ...messagesSk.error.apiValidation,
      ...apiValidation,
    },
    apiForbiddenOperation: {
      ...messagesSk.error.apiForbiddenOperation,
      ...apiForbiddenOperation,
    },
    jsValidation: {
      ...messagesSk.error.jsValidation,
      ...jsValidation,
    },
  },
}
```

### Pluralization
- choices are separated by `|`
- `t('key', n)` picks the form and passes the number as `{count}` and `{n}`; `t('key', { count })` and `t('key', { count }, count)` pick the form from `count` too
- `slovakPluralizationRule` picks by the number of choices:
  - 3: `1 | 2-4 | 0, 5+`, e.g. `"{count} nepotvrdená zmena | {count} nepotvrdené zmeny | {count} nepotvrdených zmien"`
  - 4: `0 | 1 | 2-4 | 5+`, e.g. `"žiaden deň | {n} deň | {n} dni | {n} dní"`
  - 2: `1 | other`
- languages without a rule (`en`) use the vue-i18n default: 2 choices `1 | other`, 3 choices `0 | 1 | 2+`, so write English with two
- common-admin components translate through the admin's instance, so its `pluralRules` decide their forms too: without `sk` a Slovak text comes out as "1 nepotvrdené zmeny"
- when you enable Czech, add `cs: slovakPluralizationRule` too (same plural categories)

### Anzu api entities
As anzu api work with specific response formats, in admins follow these rules:
- always put translation to system key:
```ts
cms: {
  site,
  job,
  article,
  rubric
  // and more
}
weather: {
  location,
  locationGroup
  // etc
}
```
- inside of translation, always put entity fields inside of `model` key and filters inside of `filter` key, because validation errors are translated using this structure, example:
```json
{
  "filter": {
    "id": "Id",
    "title": "Title"
  },
  "model": {
    "id": "Id",
    "title": "Title",
    "domain": "Domain"
  }
}
```
- the keys are built from system and entity (subject):
  - validation errors: `<system>.<entity>.model.<field>`
  - form fields without `label` inside `<ASystemEntityScope system="cms" subject="article">`: `<system>.<subject>.model.<field>`
  - `createDatatableColumnsConfig` column titles: `<system>.<subject>.model.<key>`
  - `createFilter` labels: `<system>.<subject>.filter.<name>`
- other fields are mostly up to you, but try to check and follow existing translations in admins

### Adding a language
In common-admin:
- add it to `LanguageCode` and `ALL_LANGUAGES` in [`src/domains/system/composables/languageSettings.ts`](../../src/domains/system/composables/languageSettings.ts)
- add `src/locales/<code>.ts` with its `src/locales/<code>/` folder
- export `messages<Code>` from [`src/lib.ts`](../../src/lib.ts)
- if the language needs a plural rule, add it to `pluralRules` in [`src/plugins/i18n.ts`](../../src/plugins/i18n.ts) and in the admins' `@/plugins/i18n`
- optionally a flag in [`FlagCountry.vue`](../../src/domains/system/flags/components/FlagCountry.vue) (only `sk` and `en` have one)
