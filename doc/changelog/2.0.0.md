2.0.0 — unreleased
===

The first release with a changelog. Changes are tracked from this version on, one file per release; releases before 2.0.0 have no reliable record.

From 2.0.0 on, releases follow the [versioning described in the README](../../README.md#versioning).

### Contents

Vue 3 and Vuetify building blocks shared by the anzusystems admins, most used first:
- **List views** — filters (`createFilterStore`, `createFilter`, `AFilterWrapper`, `AFilterString` and the other filter fields), pagination and ordering (`usePagination`, `ADatatablePagination`, `ADatatableOrdering`, `ADatatableConfigButton`)
- **Detail and layout** — `ACard`, `ARow`, `ACopyText`, `ABooleanValue`, `ADatetime`, chips (`AChipNoLink`, `ACachedChip`), `ADialogToolbar`
- **Types and utils** — ids and dates (`IntegerId`, `DocId`, `DatetimeUTC`), type guards (`isUndefined`, `isNull`, …), string, date and object helpers
- **App plumbing** — `defineBreadcrumbs`, `useAlerts`, `defineCached`, the `AnzuSystemsCommonAdmin` plugin
- **Buttons** — toolbar actions (`AActionSaveButton`, `AActionCloseButtonHistory`, …) and table row actions (`ATableCopyIdButton`, …)
- **Forms** — `AFormTextField`, `AFormTextarea`, `AFormValueObjectOptionsSelect`, `AFormRemoteAutocomplete`, `AFormDatetimePicker`, `ASystemEntityScope`, validation with `useValidate`
- **API** — `useApiRequest`, `useApiFetchList`, `useApiFetchByIds`, `useApiFetchItems`, `useApiCommand` and the errors they throw
- **Shared screens** — list editors (`AListEditor`, `ASortableListEditor`), the unsaved changes guard, users, permission groups, logs and jobs
- **DAM and collaboration** — image widgets, asset select, upload queue, collaborative editing

And more: sk, en and cs messages, the Vuetify config (`useCommonVuetifyConfig`), themes, Sentry (also for the admins' builds, with the library's source maps: `anzuSentry` from `@anzusystems/common-admin/vite`), and an eslint plugin for the consumers (`recommended()`).

### Packaging

- **One file per module.** `dist/` mirrors `src/` (bundled dependencies under `dist/vendor/`) and `package.json` declares `"sideEffects": ["**/*.css"]`, so an admin's bundler keeps what the admin imports and leaves the rest. Importing from `@anzusystems/common-admin` stays the same.
- **Sources by domain**: `src/domains/<domain>/`, `src/shared/`, `src/plugins/`, as in the admins; `labs/` is gone, and so is `labs` in the names the library keeps in the browser. The users and permission groups lists (`AAnzuUserDatatable`, `APermissionGroupDatatable`) therefore start once with the default filter and columns; their Pinia stores are `commonAdmin…`.
- **Explicit entry points**: `.`, `./styles`, `./eslint`, `./oxlint`, `./testing`, `./vite` and `./package.json`; any other path into the package no longer resolves.
- **Build tooling for the admins** in `./vite`: `anzuSentry` (release, hidden source maps, upload) and the library's own source maps chained into the admin's, so Sentry shows frames from common-admin as its sources.
- **Loaded on first use**: the bookmark dialog's list editor, the upload queue's region editor with cropper.js, and rusha, which hashes an upload. A page that only shows the bookmark button or the upload queue no longer carries them; the editors show a spinner the first time and offer a retry when their chunk does not arrive in time. After a failed fetch, a retry works in browsers that no longer keep the failed import; older ones need a page reload. rusha loads when a file starts uploading, before its asset is created, so a load that fails or times out fails the item without leaving an empty asset.
- **socket.io-client is not a dependency**: collaboration takes `io` from the admin (`collab.io` in the plugin options), so only an admin with collaboration installs it.
- **cropper.js 2.3.1** in the region editor (bundled; the dependency is `cropperjs` again, the `cropperjs2` alias of the days beside v1 is gone). A resize is measured from where its drag started: a crop dragged past the image's edge and back stays at the edge until the pointer is back over it, where it used to shrink at once.

### Changed — migrating an admin

All six admins are migrated in their working trees; the list is what another consumer has to do.

- **i18n: one instance, the admin's.** The plugin takes the admin's `i18n` (`app.use(AnzuSystemsCommonAdmin, { i18n, … })`, composition mode) and translates through it, so the library follows the admin's language switch. The admin's locale files include the library's messages (`messagesSk`, `messagesEn`, `messagesCs`), as before. `modifyLanguageSettings` acts on that instance: `setLanguage` stores the choice but switches `locale` only once that language's messages are loaded (`'xx'` at once), and `addMessages` switches when the stored language's messages arrive — no raw keys between the click and the reload. `i18n` and `useI18n` are no longer exported — import `useI18n` from `vue-i18n`. The library's own `DefineLocaleMessage` augmentation is not published, so it no longer clashes with the admin's. Installed without `i18n`, the plugin warns: its texts would render as keys.
- **Alerts: one host, `VSnackbarQueue`.** `AAlerts` renders its queue through Vuetify's `VSnackbarQueue`: up to `max` (5) alerts at once, a newer one pushes out the oldest; alerts raised before a host is mounted, e.g. during start-up, wait for it. Mount exactly one `<AAlerts />`, outside any layout switch (the admins mount it in `AppLayout.vue`).
- **CSS in a cascade layer.** The library's stylesheet is one layer, `anzu-common`, and brings Vuetify's reset in `vuetify-core.reset`. Name the layer in the admin's `@layer` statement, between `vuetify-overrides` and `vuetify-utilities`, so a Vuetify utility in a template beats library styles. Declare Vuetify's sub-layers right after it in the same `<style>` (the four statements in [installation](../guide/installation.md)): Vuetify's component stylesheets name them too, and without the declaration the first one to load decides their order. An admin's unlayered CSS now beats the library's normal declarations, while the library's `!important` ones beat an admin's `!important`. In expanded or edited list editor rows, utility classes in the admin's slot content now win over the row's highlight.
- **Utility classes.** `system-border-{t,b,l,r,a}` → Vuetify `border-t`, `border-b`, `border-s`, `border-e`, `border`; `line-clamp-1` → `text-truncate`; `line-clamp-2` → `a-line-clamp-2`; `required`/`required-mark` → `a-required-mark`. Removed: `system-border-x/y`, `line-clamp-3/4`, `cursor-pointer` (Vuetify has its own), `white-space-pre`, `image-loading-effect`, `v-toolbar--custom-tiny`.
- **Emits without the `on` prefix**: `ACachedChip` (`close`), `ACreateDialog` (`confirm`, `open`, `close`, `error`, `success`), `ADialogToolbar` (`cancel`), `ABtnSplit` (`click`), `ADatetimePicker` (`open`, `close`), `ASubjectSelect` (`open`, `pageChange`, `confirm`, `fetchNextPage`), `AAssetSelect` (`confirm`); `@on-confirm` becomes `@confirm`.
- **Renamed exports.** Exported components start with `A`: `Dam*` → `ADam*` (10 components), `FiltersSelected` → `AFiltersSelected`, `ImageMassOperations` → `AImageMassOperations`. Injection keys: `SystemScopeSymbol` → `SystemScopeKey`, `SubjectScopeSymbol` → `SubjectScopeKey`, `ImageWidgetUploadConfig` → `ImageWidgetUploadConfigKey`.
- **`ANestedSortableListEditor`**: the legacy aliases (`addAfterId`, `addChildToId`, `removeById`, `updateData`, `resetDirtyBaseline`, `clearUnsavedState`, `hasUnsavedChanges`) are gone. After the backend saved a row, call `acceptChanges(op, keys)`; the handle type is `ExposedNestedSortableListEditorHandle`.
- **`Acl` values are typed by the admin**: declare `interface AclRegistry { acl: AclValue }` in a module augmentation of `@anzusystems/common-admin`; `<Acl :permission>` and `Permissions<TAcl>` check against it. `Acl`, `AChipNoLink` and the `ABtn*` aliases are declared by the package; an admin's own declarations of them are redundant and can go.
- **Typed public API**: `UploadQueueItem.latestChunkAbortController` (`AbortController`) replaces the axios `CancelToken` source; date helpers take `DateDiffUnit` instead of dayjs types; form components type `v` as `AFormFieldValidation` (`ACreateDialog`: `ACreateDialogValidation`); `useRouteHistory` (its blacklist too) and `AActionCloseButtonHistory` take route names (`RouteRecordName`) and keep `RouteHistoryEntry` records.
- **`AImageMediaWidget` in a collaboration room** releases its field with `{ image, media }` (`ImageMediaCollabValue`) instead of the image id: an admin that applies the field's room data itself reads both halves (cms sets `leadImage` and `media`), and one that writes it under the field's path as it is would put the object into an id field.
- **`useCollabState()`** returns only its public state; the socket.io event and callback types are no longer exported.
- **Removed types**: `SortableNested`, `SortableNestedItem`, `SortableItemWithParentDataAware`, `FilterStore` (cms keeps its own, named after its domain).
- **Removed props**: `dialogMaxWidth` and `dialogZIndex` of `AActionDeleteButton` (never applied); the `trim` attribute of the text fields (it never trimmed); `onDetailLoadedCallback` of `AAssetSelect` and `AAssetListInner` (not called: a click on a tile or a table row reads the asset without it).
- **Declarations per module.** `dist/` has one `.d.ts` per module next to its JavaScript; slot props that read as `any` are typed now, go-to-definition lands in the component's own file. The augmentations target `vue` instead of `@vue/runtime-core`.
- **Peer dependencies** complete: `vuetify` at least 4.0.5 (the first with types for `vuetify/styles`), new `@mdi/font`, new optional `socket.io-client` (collaboration) and `@vueuse/shared` (named by the declarations, comes with `@vueuse/core`).
- **eslint**: `globalComponentNames` from `@anzusystems/common-admin/eslint` replaces reading the component names out of the bundle.
- **Tooltips on touch screens** no longer open on hover or focus (defaults in `useCommonVuetifyConfig`); the CSS rule that hid every tooltip there is commented out until tested on devices.
- **Created and modified rows**: `AUserAndTimeTrackingFields` takes `data` typed as `UserAndTimeTrackingData` (every field optional and nullable) instead of `any`, and `hideCreatedAt`/`hideModifiedAt` hide the date, not the whole row. `ACachedUserChip` (now exported) takes `getCachedFn`, the cache getter, instead of the `cachedUsers` map. `defineCached` takes `options` after `maxLimit`; a cache of users passes `{ retryNotFound: false }` (see Fixed). Its `immediateFetch()` waits for the batches already in flight and answers with their items too, since their ids are no longer sent twice; it rejects only for its own batch, so a caller checks `isUnresolved(id)` for the others.
- **Upload works without the notification service.** The upload queue learns what became of a file by asking the server: one poll per queue, for as long as the queue is open and the tab is visible, first 5 s after the youngest waiting item, then at 10, 16, 23, 31, 40, 50 and 60 s, every 30 s to 5 min, every minute to 20 min, every 2 min to an hour, then every 10 min; the waiting items of one licence go in one request (up to 50). `coreDam.notification` is optional: the service is used only with a non-empty `webSocketUrl` and `enabled` either `true` or the text "true" in any letter case, whitespace around it ignored (`"True"`, `" TRUE "`, as a deployment variable renders a boolean; `"false"`, `"1"` and any other value leave it off, where any text used to switch it on), and the poll is then only a backup (10, 30 and 60 s, every minute to 5 min, every 3 min to 20 min, every 5 min to an hour, then every 10 min; the dense rhythm again while the socket is not open). `uploadStatusFallback` is deprecated and no longer read: the poll cannot be switched off, and the refresh button stays in both modes. Without the service the metadata form of an item opens when its file is processed (with it at the metadata notification, as before). An item whose finish request failed without an answer of the server (a network error, a timeout) or with a 5xx one is asked about as well and becomes an uploaded one when the server finished the file, while a finish request the server refused (4xx) is final and such an item only failed; an asset missing from three reads fails the item; an item processing for 20 minutes says so and is read on (`uploadErrors.processingTooLong`); after three failed reads an item without its metadata says the data could not be loaded (`uploadErrors.readFailed`). Of the reads the poll and the notifications make, a failure is handed to the api error logger once per streak (the first that is written down: a timeout, a 401 or a 403, which `report` keeps from the logger, begins none; a read that answers ends the streak), and a missing asset once per item, while the refresh button reports each of its own; for such a caller `execute({ report: false })` of `useApiRequest` and `useApiCommand` throws a failure without handing it to the logger. For an application with a queue of its own: `createUploadSettlement`, `uploadSettlementRuntime`, `UPLOAD_POLL_SCHEDULE`, `UploadRowRole`, `useDamNotificationsConnection` and their types are exported; its settlement profile says which failures of its readers were written down with `readers.failureReported` (the library's store gives it `apiErrorIsReported`; without it every failure of a read let report counts as written).
- **What an admin's `imageApi` is handed.** `createImage`, `updateImage` and `bulkUpdateImages` get the fields of the image and nothing else: `texts`, `flags`, `dam`, and `position` and `id` when the image has them. `authorIds` and `assetId` of the upload mapping went along, in the multi-image widget also `key`, `damAuthors` and `showDamAuthors`, and an image the widget had read first went back as the whole object the admin's `fetchImage` or `fetchImageListByIds` had returned, the admin's own fields included (in cms `ownerResourceName`, `ownerResourceId`, `site`, `siteGroup`, `removedAt`, which core-cms does not read on an update): an `updateImage` or `bulkUpdateImages` that reads a field of its own from what it is handed no longer finds it there. `AImageWidget`, `AImageMediaWidget` and `AImagePublicInput` show the image `createImage` answered with instead of reading it again: `fetchImage` is not called after a create (any other change of the id is read as before), the preview no longer falls back to the placeholder in between, and a second read that fails no longer shows an error after a save that went through.
- **`AImagePublicInput` under a named configuration** reads the DAM options under that name too — the client, the address of the asset, the label and the validations of the source and the description, which it took from `default`: the name has to be in `coreDam.configs` as well as in `image.configs`, and with a name that is only in `image.configs` the component throws at setup.
- **The store `ADamAssetImageRoiSelect` reads is `useDamImageRoiStore`** (Pinia id `commonAdminDamImageRoiStore`, was `damImageRoiStore`). An admin that defined its own store under the old id to fill it (admin-dam) fills the exported store instead: with its own, the editor of the region stays empty.
- **The library's Pinia store ids all start with `commonAdmin`**: `commonAdminAssetDetailStore` (was `commonAssetDetailStore`), `commonAdminImageMediaWidgetStore` (was `commonImageMediaWidgetStore`), `commonAdminImageStore` (was `commonImageStore`), `commonAdminUploadQueuesStore` (was `commonUploadQueuesStore`) and `commonAdminFilterBookmarkStore` (was `filterBookmarkStore`); the names of the exports stay. An admin that defined a store under one of the old ids no longer shares it with the library.
- **Two rules more in the admins' lint config.** oxlint `arrow-body-style` (`as-needed`, in `./oxlint`): `() => x`, not `() => { return x }` — `oxlint --fix` rewrites them. eslint `vue/define-emits-declaration` asks for the named tuples `defineEmits<{ close: []; select: [id: number] }>()` (`type-literal`) instead of call signatures `(e: 'close'): void`; it has no fix.
- **Peer dependencies**: `@sentry/vue` and `@sentry/vite-plugin` at least 11.9.0.
- **`useApiFetchList` writes the pagination of its newest call only** (`totalCount`, `hasNextPage`, `currentViewCount`), where every call wrote its own, so two lists fetched at the same time need an instance each.

### Added
- **`createAnzuVuetify({ i18n, defaults })`** — the Vuetify instance the six admins created in their own `vuetify.ts` (the same in all six, admin-ugc adding `VDataTableServer` defaults): the common aliases, theme and defaults (`defaults` merged over them per component), `Intersect`, and the vue-i18n locale adapter, typed without the `@ts-ignore` the copies carried. The admin keeps importing the stylesheets.
- **Token refresh**: `createRefreshSession` (single flight; only a 401, or a 400 while no other tab rotated the token, ends the session; anything else is `auth-unavailable`) and `createRefreshRequestInterceptor` (logs out once per refused refresh; returns the interceptor with the `options` whose `runWhen` keeps it off `skipUrlPrefix`), with `SessionExpiredError`, `AuthUnavailableError` and `isInCauseChain`. The api error log skips requests stopped because the session is gone, as it skips 401s, and `showErrorsDefault` shows nothing for them; a request stopped because the sign-in server does not answer shows one "sign-in server is not responding" alert per outage instead of a "system error" for each. After a 400 it gives the other tab's cookie up to a second to arrive, since that tab's answer can come after this one's. A request whose signal is aborted while it waits for the refresh (its page is gone) ends as cancelled, as it would on its way out, instead of failing with the refresh's error on the page the user went to.
- **App shell**: `ALayoutSwitch` renders the layout a route names in `meta.layout` (from a map, not from global registrations) and hosts the one `AAlerts`; `ALayoutLoader` is the start-up spinner; `AActionbar` renders breadcrumbs and buttons into `AActionbarTarget` in the app bar (`resolveBreadcrumbRoute` for an admin that links breadcrumbs its own way). Both sit on `createTeleportSlot`, which holds its target element instead of looking it up by selector, so a source without a mounted target renders nothing instead of warning; the actionbar target keeps `id="anzu-actionbar"`, which the admins' e2e suites select by.
- **Remote autocompletes of one entity**: `createRemoteAutocomplete({ name, useSelectActions, useInnerFilter, filterByField, prefetch, filterSortBy, defaults, zeroIsEmpty })` and `createFilterRemoteAutocomplete(...)` are the wrapper components the admins wrote per entity; the caller's props, listeners and slots reach `AFormRemoteAutocomplete` / `AFilterRemoteAutocomplete` and win over `defaults`. The result is typed with the autocomplete's props, so the call sites keep their type checks. A list scoped by a parent takes the component's own `props`, `filterFromProps` (the inner filter follows the props, written before the first fetch) and `scope` (`of` keys the autocomplete so a changed scope refetches, the model is cleared from a set scope unless `reset: false`, `requiredWhen` disables it while unset). The autocomplete's events (`blur`, `focus`, `searchChange`, `searchChangeDebounced`) are typed on the result as well
- **Start-up**: `startWithEnvConfig(apply, start)` loads `config.json` (never from a cache, with the admins' checks), applies it and runs the admin's start; either failing shows the fatal error in `#app`. A failed start is reported through `reportError`, so an error handler already installed (Sentry's, once initialized) sees it, where the admins' loaders logged it as a config that did not load.
- **Reload on a new version**: `checkForNewVersion()` reloads the page when `ASystemBar` has seen a new `appVersion` (for a route guard, which then parks the navigation for `RELOAD_VETO_GRACE`), through `requestAppReload()`, which reloads at most once per 30 s so a reload that does not take cannot loop. Each admin carried both as copies.
- **Api clients**: `defineApiClient(() => ({ config, request, response }))` is the lazy axios client the admins wrote by hand, 29 times: the instance is created on the first call and its interceptors are registered once. `config` is passed to `axios.create` as it is, nothing is added. `skipUrlPrefixes(...prefixes)` is the `runWhen` that keeps an interceptor off the auth endpoints.
- **Guard tests for the admins** in `./testing` (vitest, an optional peer): `describeGeneratedRoutes`, `describeCloseButtons`, `describeRouteHistory`, `describeSortableLists`, `describeAlertHost` and `describeCssLayerOrder` are the tests each admin carried as a copy; an admin's test file now passes its globs and its route history blacklist. The list editors' unsaved lifecycle test moved into the library. `describeSortableLists` reads each editor's tag on its own (an apostrophe in a comment no longer hides the tags after it) and leaves out an editor handed a lifted controller (`:editor`), which the owner of the controller registers. `describeCssLayerOrder` also fails a stylesheet, a style or a rule before the `@layer` statements, and requires Vuetify's sub-layer order right after the top-level one (`CSS_LAYER_STATEMENTS`): layers are ordered by first mention, so anything earlier that names a layer would decide the order instead -- a cms build had `vuetify-final.trumps` below `.transitions`, named first by a component stylesheet. `describeDeclaredDependencies` (new) fails on an import or a module augmentation (`declare module '…'`) of a package the admin's `package.json` does not declare, which only a hoisting `node_modules` resolves.
- **Watch into an admin**: `yarn dev:admin` rebuilds the library (as one bundle, ~0.5 s) into the admins' `node_modules` on every change, and `commonAdminDevWatch()` from `./vite` reloads the admin's page with it: ~1.3 s with `prebundle: false`, ~4.5 s pre-bundled (measured on admin-blog, yarn and pnpm). Safe under pnpm: files are replaced, never written into, so pnpm's global store stays untouched. A restart that `commonAdminDevWatch()` starts no longer keeps the previous server's module graphs in memory (+45–100 MB a restart; a workaround for [vitejs/vite#23493](https://github.com/vitejs/vite/issues/23493) until Vite releases the fix); Vite's own restarts (a config change, `r`) still do.
