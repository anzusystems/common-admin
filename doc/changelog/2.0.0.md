2.0.0 — unreleased
===

The first release with a changelog. Changes are tracked from this version on, one file per release; releases before 2.0.0 have no reliable record.

From 2.0.0 on, releases follow the [versioning described in the README](../../README.md#versioning).

### Contents

Vue 3 and Vuetify building blocks shared by the anzusystems admins, most used first:
- **List views** — filters (`createFilterStore`, `createFilter`, `AFilterWrapper`, `AFilterString` and the other filter fields), pagination and ordering (`usePagination`, `ADatatablePagination`, `ADatatableOrdering`, `ADatatableConfigButton`)
- **Detail and layout** — `ACard`, `ARow`, `ACopyText`, `ABooleanValue`, `ADatetime`, chips (`AChipNoLink`, `ACachedChip`), `ADialogToolbar`
- **Types and utils** — ids and dates (`IntegerId`, `DocId`, `DatetimeUTC`), type guards (`isUndefined`, `isNull`, …), string, date and object helpers
- **App plumbing** — `defineBreadcrumbs`, `useAlerts`, `defineCached`, the `AnzuSystemsCommonAdmin` plugin
- **Buttons** — toolbar actions (`AActionSaveButton`, `AActionCloseButtonHistory`, …) and table row actions (`ATableCopyIdButton`, …)
- **Forms** — `AFormTextField`, `AFormTextarea`, `AFormValueObjectOptionsSelect`, `AFormRemoteAutocomplete`, `AFormDatetimePicker`, `ASystemEntityScope`, validation with `useValidate`
- **API** — `useApiRequest`, `useApiFetchList`, `useApiFetchByIds`, `useApiFetchItems`, `useApiCommand` and the errors they throw
- **Shared screens** — list editors (`AListEditor`, `ASortableListEditor`), the unsaved changes guard, users, permission groups, logs and jobs
- **DAM and collaboration** — image widgets, asset select, upload queue, collaborative editing

And more: sk, en and cs messages, the Vuetify config (`useCommonVuetifyConfig`), themes, Sentry (also for the admins' builds, with the library's source maps: `anzuSentry` from `@anzusystems/common-admin/vite`), and an eslint plugin for the consumers (`recommended()`).

### Packaging

- **One file per module.** `dist/` mirrors `src/` (bundled dependencies under `dist/vendor/`) and `package.json` declares `"sideEffects": ["**/*.css"]`, so an admin's bundler keeps what the admin imports and leaves the rest. Importing from `@anzusystems/common-admin` stays the same.
- **Sources by domain**: `src/domains/<domain>/`, `src/shared/`, `src/plugins/`, as in the admins; `labs/` is gone, and so is `labs` in the names the library keeps in the browser. The users and permission groups lists (`AAnzuUserDatatable`, `APermissionGroupDatatable`) therefore start once with the default filter and columns; their Pinia stores are `commonAdmin…`.
- **Explicit entry points**: `.`, `./styles`, `./eslint`, `./oxlint`, `./testing`, `./vite` and `./package.json`; any other path into the package no longer resolves.
- **Build tooling for the admins** in `./vite`: `anzuSentry` (release, hidden source maps, upload) and the library's own source maps chained into the admin's, so Sentry shows frames from common-admin as its sources.
- **Loaded on first use**: the bookmark dialog's list editor, the upload queue's region editor with cropper.js, and rusha, which hashes an upload. A page that only shows the bookmark button or the upload queue no longer carries them; the editors show a spinner the first time and offer a retry when their chunk does not arrive in time. After a failed fetch, a retry works in browsers that no longer keep the failed import; older ones need a page reload. rusha loads when a file starts uploading, before its asset is created, so a load that fails or times out fails the item without leaving an empty asset.
- **socket.io-client is not a dependency**: collaboration takes `io` from the admin (`collab.io` in the plugin options), so only an admin with collaboration installs it.

### Changed — migrating an admin

All six admins are migrated in their working trees; the list is what another consumer has to do.

- **i18n: one instance, the admin's.** The plugin takes the admin's `i18n` (`app.use(AnzuSystemsCommonAdmin, { i18n, … })`, composition mode) and translates through it, so the library follows the admin's language switch. The admin's locale files include the library's messages (`messagesSk`, `messagesEn`, `messagesCs`), as before. `modifyLanguageSettings` acts on that instance: `setLanguage` stores the choice but switches `locale` only once that language's messages are loaded (`'xx'` at once), and `addMessages` switches when the stored language's messages arrive — no raw keys between the click and the reload. `i18n` and `useI18n` are no longer exported — import `useI18n` from `vue-i18n`. The library's own `DefineLocaleMessage` augmentation is not published, so it no longer clashes with the admin's. Installed without `i18n`, the plugin warns: its texts would render as keys.
- **Alerts: one host, `VSnackbarQueue`.** `AAlerts` renders its queue through Vuetify's `VSnackbarQueue`: up to `max` (5) alerts at once, a newer one pushes out the oldest; alerts raised before a host is mounted, e.g. during start-up, wait for it. Mount exactly one `<AAlerts />`, outside any layout switch (the admins mount it in `AppLayout.vue`).
- **CSS in a cascade layer.** The library's stylesheet is one layer, `anzu-common`, and brings Vuetify's reset in `vuetify-core.reset`. Name the layer in the admin's `@layer` statement, between `vuetify-overrides` and `vuetify-utilities`, so a Vuetify utility in a template beats library styles. Declare Vuetify's sub-layers right after it in the same `<style>` (the four statements in [installation](../guide/installation.md)): Vuetify's component stylesheets name them too, and without the declaration the first one to load decides their order. An admin's unlayered CSS now beats the library's normal declarations, while the library's `!important` ones beat an admin's `!important`. In expanded or edited list editor rows, utility classes in the admin's slot content now win over the row's highlight.
- **Utility classes.** `system-border-{t,b,l,r,a}` → Vuetify `border-t`, `border-b`, `border-s`, `border-e`, `border`; `line-clamp-1` → `text-truncate`; `line-clamp-2` → `a-line-clamp-2`; `required`/`required-mark` → `a-required-mark`. Removed: `system-border-x/y`, `line-clamp-3/4`, `cursor-pointer` (Vuetify has its own), `white-space-pre`, `image-loading-effect`, `v-toolbar--custom-tiny`.
- **Emits without the `on` prefix**: `ACachedChip` (`close`), `ACreateDialog` (`confirm`, `open`, `close`, `error`, `success`), `ADialogToolbar` (`cancel`), `ABtnSplit` (`click`), `ADatetimePicker` (`open`, `close`), `ASubjectSelect` (`open`, `pageChange`, `confirm`, `fetchNextPage`), `AAssetSelect` (`confirm`); `@on-confirm` becomes `@confirm`.
- **Renamed exports.** Exported components start with `A`: `Dam*` → `ADam*` (10 components), `FiltersSelected` → `AFiltersSelected`, `ImageMassOperations` → `AImageMassOperations`. Injection keys: `SystemScopeSymbol` → `SystemScopeKey`, `SubjectScopeSymbol` → `SubjectScopeKey`, `ImageWidgetUploadConfig` → `ImageWidgetUploadConfigKey`.
- **`ANestedSortableListEditor`**: the legacy aliases (`addAfterId`, `addChildToId`, `removeById`, `updateData`, `resetDirtyBaseline`, `clearUnsavedState`, `hasUnsavedChanges`) are gone. After the backend saved a row, call `acceptChanges(op, keys)`; the handle type is `ExposedNestedSortableListEditorHandle`.
- **`Acl` values are typed by the admin**: declare `interface AclRegistry { acl: AclValue }` in a module augmentation of `@anzusystems/common-admin`; `<Acl :permission>` and `Permissions<TAcl>` check against it. `Acl`, `AChipNoLink` and the `ABtn*` aliases are declared by the package; an admin's own declarations of them are redundant and can go.
- **Typed public API**: `UploadQueueItem.latestChunkAbortController` (`AbortController`) replaces the axios `CancelToken` source; date helpers take `DateDiffUnit` instead of dayjs types; form components type `v` as `AFormFieldValidation` (`ACreateDialog`: `ACreateDialogValidation`); `useRouteHistory` (its blacklist too) and `AActionCloseButtonHistory` take route names (`RouteRecordName`) and keep `RouteHistoryEntry` records.
- **`AImageMediaWidget` in a collaboration room** releases its field with `{ image, media }` (`ImageMediaCollabValue`) instead of the image id: an admin that applies the field's room data itself reads both halves (cms sets `leadImage` and `media`), and one that writes it under the field's path as it is would put the object into an id field.
- **`useCollabState()`** returns only its public state; the socket.io event and callback types are no longer exported.
- **Removed types**: `SortableNested`, `SortableNestedItem`, `SortableItemWithParentDataAware`, `FilterStore` (cms keeps its own, named after its domain).
- **Removed props**: `dialogMaxWidth` and `dialogZIndex` of `AActionDeleteButton` (never applied); the `trim` attribute of the text fields (it never trimmed).
- **Declarations per module.** `dist/` has one `.d.ts` per module next to its JavaScript; slot props that read as `any` are typed now, go-to-definition lands in the component's own file. The augmentations target `vue` instead of `@vue/runtime-core`.
- **Peer dependencies** complete: `vuetify` at least 4.0.5 (the first with types for `vuetify/styles`), new `@mdi/font`, new optional `socket.io-client` (collaboration) and `@vueuse/shared` (named by the declarations, comes with `@vueuse/core`).
- **eslint**: `globalComponentNames` from `@anzusystems/common-admin/eslint` replaces reading the component names out of the bundle.
- **Tooltips on touch screens** no longer open on hover or focus (defaults in `useCommonVuetifyConfig`); the CSS rule that hid every tooltip there is commented out until tested on devices.
- **Created and modified rows**: `AUserAndTimeTrackingFields` takes `data` typed as `UserAndTimeTrackingData` (every field optional and nullable) instead of `any`, and `hideCreatedAt`/`hideModifiedAt` hide the date, not the whole row. `ACachedUserChip` (now exported) takes `getCachedFn`, the cache getter, instead of the `cachedUsers` map. `defineCached` takes `options` after `maxLimit`; a cache of users passes `{ retryNotFound: false }` (see Fixed). Its `immediateFetch()` waits for the batches already in flight and answers with their items too, since their ids are no longer sent twice; it rejects only for its own batch, so a caller checks `isUnresolved(id)` for the others.

### Added
- **`createAnzuVuetify({ i18n, defaults })`** — the Vuetify instance the six admins created in their own `vuetify.ts` (the same in all six, admin-ugc adding `VDataTableServer` defaults): the common aliases, theme and defaults (`defaults` merged over them per component), `Intersect`, and the vue-i18n locale adapter, typed without the `@ts-ignore` the copies carried. The admin keeps importing the stylesheets.
- **Token refresh**: `createRefreshSession` (single flight; only a 401, or a 400 while no other tab rotated the token, ends the session; anything else is `auth-unavailable`) and `createRefreshRequestInterceptor` (logs out once per refused refresh; returns the interceptor with the `options` whose `runWhen` keeps it off `skipUrlPrefix`), with `SessionExpiredError`, `AuthUnavailableError` and `isInCauseChain`. The api error log skips requests stopped because the session is gone, as it skips 401s, and `showErrorsDefault` shows nothing for them; a request stopped because the sign-in server does not answer shows one "sign-in server is not responding" alert per outage instead of a "system error" for each. After a 400 it gives the other tab's cookie up to a second to arrive, since that tab's answer can come after this one's. A request whose signal is aborted while it waits for the refresh (its page is gone) ends as cancelled, as it would on its way out, instead of failing with the refresh's error on the page the user went to.
- **App shell**: `ALayoutSwitch` renders the layout a route names in `meta.layout` (from a map, not from global registrations) and hosts the one `AAlerts`; `ALayoutLoader` is the start-up spinner; `AActionbar` renders breadcrumbs and buttons into `AActionbarTarget` in the app bar (`resolveBreadcrumbRoute` for an admin that links breadcrumbs its own way). Both sit on `createTeleportSlot`, which holds its target element instead of looking it up by selector, so a source without a mounted target renders nothing instead of warning; the actionbar target keeps `id="anzu-actionbar"`, which the admins' e2e suites select by.
- **Remote autocompletes of one entity**: `createRemoteAutocomplete({ name, useSelectActions, useInnerFilter, filterByField, prefetch, filterSortBy, defaults, zeroIsEmpty })` and `createFilterRemoteAutocomplete(...)` are the wrapper components the admins wrote per entity; the caller's props, listeners and slots reach `AFormRemoteAutocomplete` / `AFilterRemoteAutocomplete` and win over `defaults`. The result is typed with the autocomplete's props, so the call sites keep their type checks. A list scoped by a parent takes the component's own `props`, `filterFromProps` (the inner filter follows the props, written before the first fetch) and `scope` (`of` keys the autocomplete so a changed scope refetches, the model is cleared from a set scope unless `reset: false`, `requiredWhen` disables it while unset). The autocomplete's events (`blur`, `focus`, `searchChange`, `searchChangeDebounced`) are typed on the result as well
- **Start-up**: `startWithEnvConfig(apply, start)` loads `config.json` (never from a cache, with the admins' checks), applies it and runs the admin's start; either failing shows the fatal error in `#app`. A failed start is reported through `reportError`, so an error handler already installed (Sentry's, once initialized) sees it, where the admins' loaders logged it as a config that did not load.
- **Reload on a new version**: `checkForNewVersion()` reloads the page when `ASystemBar` has seen a new `appVersion` (for a route guard, which then parks the navigation for `RELOAD_VETO_GRACE`), through `requestAppReload()`, which reloads at most once per 30 s so a reload that does not take cannot loop. Each admin carried both as copies.
- **Api clients**: `defineApiClient(() => ({ config, request, response }))` is the lazy axios client the admins wrote by hand, 29 times: the instance is created on the first call and its interceptors are registered once. `config` is passed to `axios.create` as it is, nothing is added. `skipUrlPrefixes(...prefixes)` is the `runWhen` that keeps an interceptor off the auth endpoints.
- **Guard tests for the admins** in `./testing` (vitest, an optional peer): `describeGeneratedRoutes`, `describeCloseButtons`, `describeRouteHistory`, `describeSortableLists`, `describeAlertHost` and `describeCssLayerOrder` are the tests each admin carried as a copy; an admin's test file now passes its globs and its route history blacklist. The list editors' unsaved lifecycle test moved into the library. `describeSortableLists` reads each editor's tag on its own (an apostrophe in a comment no longer hides the tags after it) and leaves out an editor handed a lifted controller (`:editor`), which the owner of the controller registers. `describeCssLayerOrder` also fails a stylesheet, a style or a rule before the `@layer` statements, and requires Vuetify's sub-layer order right after the top-level one (`CSS_LAYER_STATEMENTS`): layers are ordered by first mention, so anything earlier that names a layer would decide the order instead -- a cms build had `vuetify-final.trumps` below `.transitions`, named first by a component stylesheet. `describeDeclaredDependencies` (new) fails on an import or a module augmentation (`declare module '…'`) of a package the admin's `package.json` does not declare, which only a hoisting `node_modules` resolves.
- **Watch into an admin**: `yarn dev:admin` rebuilds the library (as one bundle, ~0.5 s) into the admins' `node_modules` on every change, and `commonAdminDevWatch()` from `./vite` reloads the admin's page with it: ~1.3 s with `prebundle: false`, ~4.5 s pre-bundled (measured on admin-blog, yarn and pnpm). Safe under pnpm: files are replaced, never written into, so pnpm's global store stays untouched. A restart that `commonAdminDevWatch()` starts no longer keeps the previous server's module graphs in memory (+45–100 MB a restart; a workaround for [vitejs/vite#23493](https://github.com/vitejs/vite/issues/23493) until Vite releases the fix); Vite's own restarts (a config change, `r`) still do.

- **CI** builds the package and fails when the build imports an undeclared package or the published declarations do not type-check.
- **Who created and modified a record, not only when**: `AUserAndTimeTrackingFields` draws the user next to the date when it gets the admin's user cache, and an admin gets it there through its own one-file component made by `createUserAndTimeTrackingFields({ useCachedUsers, userRouteName, userTitleFn? })`, used without further imports, as a `createCachedChip` chip. - **`ACachedChip` `#unresolved` slot** (given the `id`): what an item the cache could not resolve shows instead of `#<id>`, for a cache whose id means nothing to a reader, such as a count keyed by a doc id; the tooltip stays. A `title` given by the caller still wins
- **A page acts after an asynchronous step only while the user is still on it.** In production every page's chunk is fetched on its first visit, so a user's navigation can still be on its way when a load, a save or a socket event ends; a redirect then cancels it, and a message stays on the page the user went to.
  - **`trackNavigation(router)`**, registered as the router's first guard, follows whether a navigation is on its way (`isNavigationPending(router)`) and which page is shown: another path is another page, as the admins key their `RouterView` by the path. It returns its unregistration, for tests.
  - **`usePageNavigation()`**, in the setup of a page or of a composable it calls, gives `onPage()` and a `push`/`replace` that navigate only `onPage()` and resolve whether they got there. Registered late as a fallback when the admin did not register the tracker, it misses only the guards that run before it.
  - **`ACreateDialog`** redirects to the created record this way.
- **A detail or edit page that cannot load its record leaves it.**
  - **`handleRecordLoadError(error)`** is for the `catch` of a record's own get-one. A 404 says the record does not exist (`common.alert.recordNotFound`), a 403 that it is not the user's to see (`common.alert.recordForbidden`), and anything else gets the message `showErrorsDefault` has for it. It returns whether the page should leave: not for a stopped request or an expired session, which show nothing.
  - **`useRecordPage({ fallbackRouteName, fallbackRouteParams, skipRouteNames, loading })`** gives the page a `signal` for that get-one, aborted when the page unmounts, and `leave()`.
  - **`leave()`** goes back to the view the user came from, and only while the user is still on the record's address:
    - it skips the record's own other views (`skipRouteNames` resolved with the record's params, compared without query and hash) and the create form when it is in `skipRouteNames`, but not another record of the same entity, where the Close button skips by name;
    - it skips an address a page left the same way in the last minute, so two failing records next to each other in the history do not send the user back and forth while the backend is down;
    - it does not leave the failed address behind for the browser's Back: a step back when the target is the previous entry (compared without the hash a list's filter writes, which the step back restores), a `replace` otherwise;
    - it keeps the list's page as Close does;
    - it falls back to `fallbackRouteName`;
    - it holds `loading` up, also when it cannot land, so the unloaded record's Save and Delete never show; the page lowers it again as it unmounts, since the flag is often shared with the entity's other views.
  - **While the user navigates elsewhere** (the destination's chunk loads, a guard waits; registered with `trackNavigation`, above), `handleRecordLoadError` shows nothing and `leave()` stays put, holding `loading` up: the user's navigation decides, and the message would stay on the page the user went to. `useRecordPage` also returns `onPage()` for a redirect after the load.
  - **Library loaders:** `fetchAnzuUser`, `fetchPermissionGroup` and `useLogDetailActions().fetchData` answer `true` once loaded, `false` to leave and `undefined` when superseded or stopped. The first two take `{ signal }`. `ALogDetailView` leaves this way, to `fallbackRouteName`/`fallbackRouteParams` when given.
  - **`ANotFoundView`** has a Back button (`common.system.notFound.previousButton`) next to the home one: a step back to the app's previous entry, so the browser's Back does not return to the 404 page, or the home route in a tab opened on the bad address.
  - **`describeGeneratedRoutes`** fills a param constrained to a uuid or a log's ObjectId with a value the constraint takes. It filled everything but `\d+` with `sample`, so such a route failed the smoke test.
- **`createNavigationErrorHandler(router, { onError, onFirstNavigationError })`** for `router.onError`: a navigation that throws (a guard raising, a route's chunk or stylesheet that does not load) reached only the console, and the click did nothing visible. It reports to Sentry, reloads the page for a chunk or route stylesheet that does not load (an old tab after a deploy; at most once per 30 s through `requestAppReload`, otherwise the message) and shows "Stránku sa nepodarilo otvoriť." (`common.alert.navigationFailed`) for anything else. A failing first navigation, with only the start-up loader on screen, goes once to the admin's `onFirstNavigationError`, else reloads, and keeps the message up when the reload was just tried. The admin's callbacks cannot throw out of it; `reloadOnChunkError: false` keeps the message instead of the reload, for an admin whose page holds work a reload would lose.
- **ACL that never throws, and ACL on the shared buttons.**
  - **`canSafe(acl | acl[], subject?)`** from `defineAuth` answers `false` where `can()` throws: for a system whose current user nothing has tried to load yet, and for an `allowOwner` grant without a subject. An array is evaluated with AND. For route guards and templates that may run before their system is there. `<Acl>` uses it.
  - **`acl` and `subject` props** on `AActionCreateButton`, `AActionEditButton`, `AActionDeleteButton`, `AActionSaveButton`, `AActionSaveAndCloseButton`, `ATableEditButton` and `ATableDetailButton`: the button shows only when the current user passes the check. Without `acl` nothing changes.
  - **`useAclAllowed(acl, subject?)`**, the same check as a computed for a component of the admin's own.
  - **`createUserAndTimeTrackingFields`**: `userRouteName` may be a function, read on each render, so the creator/modifier chip links only for a user who may open that page.
- **Cross-system user writes ask the descriptor first.** `UserSystemDescriptor.canWrite(action)` (`'create' | 'update'`) lets the admin say that the current user may not write a system's accounts: `false` takes away create, enable/disable and manage in `AUserSystemPanel` and `AUserSystemOverview`, leaves the system out of the bulk enable/disable (`common.userSystem.state.noWriteRight`) and of the metadata repair, and out of the systems offered for creating an account. The bulk writes and their retries check it again just before writing, so a right that went away while a dialog was open is not used. `undefined`, or no function, keeps the probe's answer as before. `descriptorMayWrite(descriptor, action)` is exported. The metadata repair lists a differing system the operator may not write as a disabled "bez práva" row instead of leaving it out.

### Fixed
- **DAM image widgets.**
  - The licence filter of the upload and select configs counts a user of the ext. system (`userToExtSystems`) as the backend's licence voter does; such a user was refused the upload and the library.
  - A widget whose upload the user may not use shows the image read-only instead of only the "access rights error" text, which hid the image that was already there. When the licence's config does not load (the backend refuses it to a user without access to the licence), the image, or the media item of `AImageMediaWidget`, is shown read-only above the "loading config" error.
  - The region of interest in the asset detail and the upload dialog is shown without the cropper to a user without `dam_regionOfInterest_update`, whose save the backend refused; `ADamAssetImageRoiSelect` takes `readonly`. The grant is the core DAM config's `roiUpdateAcl`: by default it applies to the default `/adm/v1/roi` only, another endpoint (UGC's `/ugc/v1/roi`) checks none, and `null` turns it off. The rotation in the same tab is offered by `imageRotateAcl` the same way (`dam_image_update` for the default `/adm/v1/image`).
  - A read-only multiple image widget hides `AImageMassOperations` (the image store's `readonly`), whose changes it would not save, and still shows its images when DAM refuses their assets.
  - `readonly` on `AImageWidget`, `AImageMediaWidget` and `AImageWidgetMultiple` (and their inner components) was declared and never read: it now hides the edit, library and upload controls, the remove action, the dropzone and the inline metadata form, makes the fields of a multiple widget's images read-only, turns off its reordering, and makes `metadataConfirm()` and `saveImages()` write nothing.
- **The unsaved changes dialog names each section once** — two open rows of a list editor holding the same nested list registered its label twice, and the dialog listed it twice.
- **A wrong filter field name fails where it is given, by name** — a time interval whose `related` names a field that is not configured fails in `createFilter` instead of with a TypeError on the first query or in the selected chips; `resolveTimeIntervalFilter` names a field it cannot find; `AFilterRemoteAutocomplete` checks its `name` at setup like the other filter components (`Incorrect provide/inject config.`). The image widgets' `selectedSelectConfig` reports a missing licence config instead of a TypeError. The library compiles with `noUncheckedIndexedAccess`.
- **Upload queue**: the limit of two parallel uploads holds per queue; an item removed from the queue is stopped as a stopped upload is — one still sending no longer finishes unseen, is no longer polled afterwards and counts against the limit until it stops, and one whose status fallback waits for the asset polls no more (it went on for the tries left, holding the file); an upload stopped during its finish request stays stopped; a 0-byte file no longer blocks the queue; Stop between or during chunks no longer finishes the upload or retries; fallback polling survives a network error; licence copies get a fallback timer and a `fileId`; a failed duplicate/copy check fails the item instead of leaving it processing; the ROI loader and bulk author fill report errors.
- **Image widgets**: the multi-image widget no longer carries images from one entity to the next; `expandMetadata` keeps metadata; untranslated and wrong messages; a failed DAM config no longer reports `ready`; `loadDamPrvConfig` keeps the public config flag; `isImageWidgetUploadConfigAllowed` returns a boolean; asset select race conditions.
- **Files**: size checks for `*` and `.ext` accept a file exactly at the limit and compare the extension, whatever its case (`.JPG`), also in an `accept` list with spaces after the commas; `AFileInput`/`AFileDropzone` follow changes of `accept`/`maxSizes`.
- **Filters and lists**: the filter hash replaces the history entry and Back restores it; `type: 'string'` values stay strings; removing a chip removes the right one; `useApiQueryBuilder` uses `untilName`; `ADatatableOrdering` watches deeply; time interval options are translated; `useLogFilter` follows a new time window; `useSubjectSelect` paging on open, sort and error; remote autocompletes ignore stale answers and reset `loading`; timers stop on unmount. The page `AActionCloseButtonHistory` keeps for the list it returns to is kept only for the page it lands on: landing on a page without a list, or a navigation that was stopped or failed, left it for the next list opened, which a filtered link then opened on that page, possibly an empty one. The Close's own navigation decides now: stopped, failing or cancelled by another one, it drops the page (the navigation that cancelled it opens its list afresh); a Close from a page reached by a Close still brings the page back, and so does a second click while the first Close is under way. `useRouteHistory().navigateBack` returns where it goes and its navigation (`undefined` for a step back in the browser's history).
- **List editors**: nested move-to-position, `position: false` and `strategy`; Escape during Apply; a cancelled reorder no longer restores a deleted row, nor `reset()` a row deleted in `immediate` mode; the nested editor's children toggle is named Expand/Collapse, with `aria-expanded`; inline Save sends one request; baseline after an async load; two writes in one tick; the aliases no longer commit the whole tree.
- **Forms**: `:v` on `AFormSwitch`; remote switch/checkbox `loading` after an error and stable ids; `AActionDeleteButton` variants respect `disabled`/`loading`; `ACopyText` reports success only when copying is supported; `AAdminSwitcher` survives an HTTP error; `ACurrentUserDropdown` keeps logout visible while loading; `showApiValidationError` keeps line breaks. With `hideLabel`, `AFormRemoteSwitch` and `AFormRemoteCheckbox` take their name (`aria-label`) from the label. A `readonly` `ADatetimePicker` and `AFormDatetimePicker` offer neither the calendar nor clearing, which changed the value of a read-only field. `AFormTextField`, `AFormTextarea` and `AFormSwitch` declare `readonly` (left to a readonly `VForm` around them when not set) and `AFormTextField` `modelModifiers` (`v-model.number`), which reached Vuetify only as attributes. `AFormValueObjectOptionsSelect` shows `help` as the text fields do and applies `hideDetails`, which it declared and dropped.
- **Custom data forms**: with a named `validation-scope`, `ACustomDataForm` validates the elements behind "show all" too (they were left out, so `validate()` and the page's save passed with a required one empty); when one of them fails, that part is shown, in the form it fails in, and its "hide" button is disabled until it is fixed. "Hide" closes every form on the page that shows no such error, as "show all" opens every one. A read-only element is not validated (the server does not validate it either), a cleared number is `null` instead of `NaN` (on the client an optional number can be emptied and a required one fails `required`; the server takes `null` for an optional number only when no minimum is configured for it), and a required switch shows its message. `CustomDataValue` includes `null`: code that reads a custom value has to allow for it. In the upload dialog, the custom fields of the mass operations no longer take part in the dialog's validation, as its keyword and author inputs did not; a row whose metadata cannot be edited (the save skips it: an upload that failed, or one still waiting for its metadata) is not validated either and no longer blocks the save of the others, and a row marked failed is not editable — its metadata notification can come while the file still sends or after the failure, and the row stayed, or was made, editable, validated and saved; when its file turns out to be processed after all (the client gave up on a request the server finished), it is an uploaded row again, with its metadata loaded and its error gone, and a row the processed notification has already settled stays uploaded when that request fails afterwards; "fill empty" fills a value that is `null` or an empty list as well; and "Save" is disabled while no item of the queue would be sent (it sent nothing and reported the queue saved); and "Save and apply" hands the widget only the items settled as uploaded (a duplicate and a copy are), and is disabled while there is none — a failed one was applied too, unless a required field of its row happened to stop the save. The metadata of a processed upload is loaded into its row once — by its notification, the fallback or the refresh button, whichever answers first (a duplicate still takes the metadata of the original): a later answer replaced the keywords, authors, custom data and switches the user had set since, and so did the file notification with the single-use switch. `datesCompare` passes while either date is an empty string.
- **Auth and collaboration**: `<Acl>` with AllowOwner and no subject; `useLoginStatus` cleans up, and each navigation keeps its own verdict; the unsaved changes guard reads a `Ref` each time, and asks also when the path changes on the same route (another item's page, or a child route under a guarded parent: an admin keys its view by path and remounts it, and the changes went without a question; the query and hash alone keep the page), and its answer reaches every navigation waiting on the prompt (one started while it is open, the browser's Back, left the one before it pending for good, a Close's included); stale user/permission group loads no longer overwrite newer ones; the default api logger skips the user probe's 404; `collabRoom`, `collabInit` reconnect and `ACollabLockedByUser`. The image widgets release their collaboration lock once per lock they took — a second release was refused and read as the lock still held, so the next file drop uploaded without waiting for its lock — and take no drop while another editor holds the field. They keep the lock while an asset picked from DAM is fetched or copied into the licence — the picker closes first, and the lock went with the old value — and ask for a refused lock again on the next drop or when the menu opens. A lock taken while the room was active is released on the server when the other editor has left, also one whose request timed out, for every collab lock, text fields and `useCollabAnyDataChange` locks too (it stayed, and whoever came back found the field locked); after a lost connection the image widgets ask for it again once the room is back, and a menu or dialog opened while alone, or whose ask was refused, asks for it when another editor arrives. A drop whose wait for the lock ran out releases a lock the server may have granted late, when no other drop, menu or dialog waits for or holds it. A DAM pick that ends early no longer leaves the metadata dialog on a spinner. A dialog the image widgets open asks for the lock itself, so the `expandOptions` buttons, which open theirs with no menu, lock the field and send the confirmed value; like the menu's button, they are disabled while another editor holds the field. With `callDeleteApiOnRemove` the lock is kept till the image is deleted, through the menu's close and a dialog's, and the others get the removal; a menu or dialog still open then keeps it for its own close or confirm (in a room the editor is alone in, the removal goes to the buffer at once). The buffer of a room is dropped on a join into a room the others are in and on a leave: kept, what an editor wrote alone went out later, once that editor was the moderator again, over what the others had changed since. `COLLAB_FIELD_PREFIX_EMBED` is exported, for an admin to leave the embed locks out of its data. `useCollabField` takes `reacquireWhenActive`: a lock the component asked for and has not released is asked for again when the room turns active — back after a lost connection, or joined by another editor while this one was alone; the form fields that hold their lock while focused (text field, textarea, switch, the datetime pickers, value object select, remote autocomplete) pass it. `ImageMediaWidget` with `callDeleteApiOnRemove` deletes its own image: it read the id from the store's detail, which the widgets share, so it deleted none, or another widget's. In development `<Acl>` warns, once per permission, when its check throws and hides the content. `ALogDatatable`'s warning about a view that is not remounted now shows in an admin's development too (it read `import.meta.env.DEV`, which the library's build fixes to `false`).
- **Utils**: `getMonthInterval`, `stringIsValidEmail` with plus addresses, `stringToSlug`, `prettyDuration`, `isInt`, `arrayFlatten`, `object*ValueByPath` with `null`, `cloneDeep` with refs, `stringUrlTemplateReplace` encodes values, `parseBoolean('   ')`, `dateTimeNow(false)`, `stringSplitOnFirstOccurrence`.
- **Styles**: the selected datatable row in dark mode, `line-clamp` display, list editor and autocomplete contrast in dark mode; alerts stay above dialogs and Esc still closes a dialog while an alert is shown.
- **Fonts** load through a `<link>` instead of webfontloader.
- **`AFileInputDialog.activate()`** opens the dialog and the file choice: it reached for a ref that was never set, so an image widget with `expandOptions` did nothing on a click of its dropzone.
- **App shell and DAM notifications**: `ASystemBar` leaves no version check scheduled after its unmount (a return to the window while a retry was still pending started a second check, and only its timer was cleared); a DAM notifications handle disposed directly is forgotten, so the next `initDamNotifications()` returns a fresh handle whose `openConnection()` works, instead of the disposed one; `destroyDamNotifications` is exported again (it was dropped from 2.0 with the commented-out exports).
- **Cached items**: `defineCached` no longer asks again, on every `add()`, for what it could not resolve — a 403 or a user missing from the table cost a request and a spinner on every page showing it. An unresolved item carries its reason (`_unresolvedReason`): a forbidden one is not asked for again, a failed one is (network, timeout, 5xx, 401, a 404 of the whole request), one the server did not return is unless the cache passes `{ retryNotFound: false }`, which the library's user caches do (`useDamCachedUsers`, `useCachedAnzuUsers`). A 401, a 403, a stopped request and a lost or unavailable session are no longer written down as a failed fetch; timeouts, network failures, unexpected answers and 5xx still are. Two batches in flight no longer send the same ids (the queue was drained after the answer). A long queue goes out in batches of 100, each committed on its own, so a failing batch no longer takes the loaded ones with it; a cache over a backend that takes fewer ids a request passes `{ batchSize }`. `add()` skips `0` and `''`, which `get`, `has` and `isLoaded` treat as no id (a blank record's `createdBy: 0` went out as `filter_in[id]=0`). `addManual`/`addManualMinimal` take the id out of the queue (the fetch overwrote what was put in by hand) and prune. `useApiFetchByIds` asks in batches of 100, one after another: a cache draining a long queue built a query string past what a proxy takes. An item that could not be resolved shows `#<id>` with a tooltip and no link in `ACachedChip` and `ACachedUserChip`, which drew an empty chip; `ACachedUserChip`'s link icons were swapped.
