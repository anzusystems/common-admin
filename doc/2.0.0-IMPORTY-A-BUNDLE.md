### Codemod
- **Zoznam mien** zo `src/auto-imports.d.ts` vygenerovaného **nanovo** (plugin má `dtsMode: "append"` a v iných klonoch môže niesť staré mená) alebo priamo z `getImports()` unimportu (hodnoty aj typy); importy z `src/shared` ako `@/shared/x` (relatívne importy sú v `src` zakázané eslintom).
- **Skripty** (`.vue` aj `.ts`): rozlíšenie symbolov cez TypeScript (checker/symbol resolution) s oddeleným hodnotovým a typovým významom; **deklarácie z vygenerovaného `src/auto-imports.d.ts` sa za väzbu nepovažujú** (checker by cez ne vyriešil napr. `createApp` v `admin-blog/src/main.ts:16` bez importu a codemod by import vynechal) — codemod beží s programom bez tohto súboru alebo jeho deklarácie explicitne ignoruje; hodnota sa importuje len vtedy, keď v danom mieste nie je viazaná hodnotová deklarácia, typ len keď nie je viazaný typ. `interface ref {}` neblokuje import `ref()`; class a enum sú v oboch priestoroch; typový parameter hodnotu nezatieňuje; `export { X }` (lokálne meno — potrebuje import) sa líši od `export { X } from './m'` (nepotrebuje). Deklarácie pre celý lexikálny rozsah (aj použitie pred deklaráciou). Makrá kompilátora Vue (`defineProps`, `defineEmits`, `defineModel`, `withDefaults`, …) sú vylúčené.
- **Šablóny:** binding metadáta zo `compileScript` (props, setup premenné) + `compileTemplate` a zber `_ctx.X`; meno viazané ako prop alebo setup premenná sa **nikdy** neimportuje.
- **Pasca `readonly`:** prop `readonly` (≥ 170 SFC) — naivná detekcia by pridala `import { readonly } from 'vue'` a šablóna by sa viazala na funkciu (vždy pravdivé; napr. `NewsBodyEditor.vue` by nikdy nevykreslil editor). Lint to spoľahlivo nechytí (oxlint `vue/no-dupe-keys` v skúške áno, eslint cms nie; Vue skompiluje `v-if="readonly"` na `$setup.readonly`) — ochranou je detekcia cez metadáta a testovací prípad.
- **Typy menia runtime props:** keď je `IntegerId` a pod. importovaný namiesto globálneho, compiler-sfc typ vyrieši — napr. blog `ArticleUserImpersonateBtn.vue`: `blogId: { type: null }` → `{ type: Number }`. Dev výstup sa zmení v 269 SFC (cms 203, dam 31, inhouse 11, blog 9, forum 9, ugc 6); produkčný len v ugc `ArticleExpireAt.vue` a `ArticlePublishedAt.vue` (pridá `null` do zoznamu typov, bez dopadu). Nikde nepribudne `Boolean` ani `Function` (boolean casting sa nemení). Následok: dev a vitest začnú validovať typy props → manifest obsahuje diff runtime props pred/po a zlyhá na každom novom `Boolean`/`Function`; varovania Vue v testoch a dev prejsť.
- **Vkladanie:** do `<script setup>` (prázdny `<script setup>` — cms 4, inhouse 1, ugc 1 — nepridávať druhý); zlúčiť s existujúcim importom z toho istého modulu; typy ako samostatné `import type { … }`.
- **Netreba riešiť:** 32 `Cached…Chip.vue` v cms (len `<script>` s `export default createCachedChip({…})`, bez šablóny) a 3 SFC v ugc len so šablónou (`EmbedDialogDefault.vue`, `RegisterActions.vue`, `SidebarAppendRail.vue`) bez auto-importovaných mien. Options API, `.tsx`/`.jsx`, SFC s `<script>` aj `<script setup>`, ani `vi.mock` faktory s auto-importovanými menami sa nevyskytujú (overené); hodnotové importy medzi modulmi `src/shared` existujú (napr. ugc `src/shared/settingsStore.ts:13` importuje `AuthScope`) — pokryje ich report cyklov. `e2e/` sa netýka.
- **Manifest:** pre každý súbor pridané mená (script/šablóna/typ), diff runtime props; výnimky (zatienené mená, cielene nepridané importy) ako **revidovaný allowlist**, nie ručné poznámky. Manifest sa commitne v admine spolu s commitom B (`scripts/explicit-imports.manifest.json`) aj s commitom vstupu (commit A) a commitom skriptu v common-admin, aby sa dal neskôr prejsť. Verzie `unimport` (dnes 6.5.0, z adminu — common-admin ho nemá) a `@vue/compiler-sfc` sa zapíšu do manifestu; overovač ich musí použiť z adminu **pred** tým, ako commit B odstráni `unplugin-auto-import` z lockfilu.
- **Porovnanie väzieb šablón pre každý SFC:** skompilovať šablónu pred a po konverzii a porovnať cieľ každej referencie (`$props.x` / `$setup.x` / `_ctx.x`). Pravidlá: `_ctx.X` → `$setup.X` je očakávaná zmena a prejde **len** vtedy, keď manifest eviduje explicitný import `X` a detektor injekcií pred konverziou `X` v tom súbore potvrdil (napr. `SYSTEM_AI` v `ConsumerClientManage.vue:25`); každá iná zmena cieľa — najmä `$props.X` → `$setup.X` — je chyba (allowlist len jednotlivo s odôvodnením). Chráni pred nesprávne **pridaným** importom (napr. `readonly` nad prop — `NewsBodyEditor.vue:65`), ktorý kontrola nula injekcií nevidí.
- **Overovač nula injekcií** (deterministický, pred odstránením pluginu, po súboroch nad celým `src`, nie cez build aplikácie): pre `.ts` súbory detektor unimport nad zdrojom **po odstránení typov** (inak falošne hlási napr. `const envConfig: EnvConfig`, `readonly?:`, `typeof SYSTEM_CMS` v typoch); pre SFC oba script bloky → `compileScript` → `compileTemplate` s binding metadátami → detektor unimport (vrátane template addonu, ktorý hľadá `_ctx.X`) nad **skompilovaným** script (po odstránení typov) aj render výstupom, nie nad surovým `.vue` (plugin beží ako post-transform). Výsledok: nula zostávajúcich hodnotových injekcií, výnimky len z allowlistu. Typy pokryje `vue-tsc`.
- **Testovacie prípady:** prop rovnakého mena (overiť skompilovanú väzbu `$props.readonly`, nie `$setup.readonly`), parameter funkcie a vnorená deklarácia rovnakého mena, použitie pred deklaráciou, destrukturovanie/rest, aliasy importov, deklarácie function/class/enum/namespace, typové parametre, catch/for väzby, `typeof` v type, `export { name }` a re-exporty, object shorthand vs. kľúč vlastnosti, labely a member prístupy, `v-for` aliasy, vnorené/dynamické sloty, súbor exportujúci auto-importované meno, meno dostupné len cez vygenerovaný `auto-imports.d.ts` (`createApp` v `main.ts` — import sa musí pridať), kolízie medzi menným priestorom hodnôt a typov (`interface ref`, `type computed`, class/enum rovnakého mena), lokálny vs. zdrojový re-export, reťazce a URL, iba typové meno, typ len v pretypovaní v šablóne (`RouteDetail.vue:107`, `as IntegerId` — nájde `vue-tsc`), makrá.

## Krok 2b — zjednotená Sentry konfigurácia a source mapy knižnice
**Problém:** Sentry v adminoch ukazuje pri chybách z knižnice minifikovaný kód. Knižnica source mapy so zdrojákmi publikuje, ale produkčný build adminu (Vite/rolldown) pri súboroch z `node_modules` komentár `sourceMappingURL` ignoruje, takže mapa nahraná do Sentry končí v `dist/common-admin.js`.
**Overené na admin-blog (scratch build):** s malým pluginom, ktorý pre `@anzusystems/common-admin/dist/*.js` vráti `{ code, map }` zo susedného `.map`, sa mapy zreťazia — rovnaká pozícia v minifikovanom chunku sa namiesto `dist/common-admin.js:85` rozbalí na `src/components/ABooleanValue.vue:47`; mapa adminu odkazuje na 281 pôvodných súborov knižnice s obsahom (predtým 3 súbory `dist`).

**Dnešná konfigurácia v adminoch** (vo všetkých 6 takmer zhodná): `shouldEnableSentry = !!APP_DEPLOY_ENV && !!SENTRY_URL`; `build.sourcemap: shouldEnableSentry ? 'hidden' : false` (ugc: bez Sentry `NODE_ENV !== 'production'`); `sentryVitePlugin({ disable: !shouldEnableSentry, url, authToken, org: 'petitpress', project: 'anzu-admin-<x>', release: { name: GITVAR_SHORTVERSION }, telemetry: false, sourcemaps: { filesToDeleteAfterUpload: './dist/**/*.js.map' } })`. Mapy sú teda `hidden` (JS na ne neodkazuje) a po uploade do Sentry sa z `dist` zmažú — na produkčnú stránku sa nedostanú.

**Návrh:** common-admin exportuje `@anzusystems/common-admin/vite` (Node, bez buildu — ako `./eslint`, zo `src/vite/**`, s `.d.mts`):
- `commonAdminSourcemaps()` — plugin so zreťazením máp knižnice; aktívny len keď build generuje mapy (inak nič nerobí a build nespomalí)
- `commonAdminSourcemaps()` matchuje `dist/**/*.{js,mjs}` (dnes aj `.mjs` chunky), bez susednej mapy vráti `null`; `apply: 'build'` a filter na `load` hooku (nulová réžia pre ostatné moduly)
- `anzuSentry({ project, org = 'petitpress', release?, ...pluginOverrides })` — **synchrónne** vráti zoznam pluginov: `commonAdminSourcemaps()` + `sentryVitePlugin` so zjednotenými voľbami + `config` hook, ktorý pri zapnutom Sentry nastaví `build.sourcemap: 'hidden'`; override voľby umožnia overovací build do dočasného release (`finalize: false`) bez úpravy adminu; knižnica tak nemá natvrdo `petitpress`
- pri zapnutom Sentry (`APP_DEPLOY_ENV` && `SENTRY_URL`) `anzuSentry` zlyhá, ak je prázdny token, org alebo project (plugin by inak len zalogoval varovanie, nič nenahral a mapy aj tak zmazal); voliteľne explicitná premenná na vypnutie uploadu pre núdzový hotfix; otestovať túto cestu aj zlyhaný upload
- admin: `plugins: [...anzuSentry({ project: 'anzu-admin-blog' }), …]`, vlastné `shouldEnableSentry`, `build.sourcemap` a `sentryVitePlugin` sa odstránia; ugc sa zjednotí (bez Sentry žiadne mapy)
- `@sentry/vite-plugin` ako voliteľný peer common-admin a devDependency (kvôli typom a testom); načíta sa **synchrónne a ošetrene** (`createRequire(import.meta.url)` + `try/catch`, pri chýbajúcom peeri zrozumiteľná chyba len ak je Sentry zapnutý) — lenivý `import()` nejde, lebo `anzuSentry()` vracia pluginy synchrónne do `plugins`; `commonAdminSourcemaps` v samostatnom module bez tejto závislosti; `vite` ako voliteľný peer, ak `.d.mts` importuje typy z Vite; test `./vite` s peerom aj bez neho; `.d.mts` overiť malým typovaným konzumentom v node testoch alebo v pack teste (`skipLibCheck` ho inak nekontroluje)
- `filesToDeleteAfterUpload` sa odvodí z vyriešeného `build.outDir` (v `configResolved`; voľba prijíma Promise) — pevný `./dist/**/*.js.map` sa vyhodnocuje voči pracovnému adresáru a pri inom `outDir` by mazal zlé mapy
- poradie ako v overenej skúške: `commonAdminSourcemaps` s `enforce: 'pre'` na začiatku zoznamu pluginov (`...anzuSentry()` prvé v `plugins`); Sentry plugin má `enforce: 'pre'` vlastný
- zlyhaný upload máp musí zhodiť build (dnes plugin chybu len zaloguje a mapy v `finally` aj tak zmaže) — `errorHandler`, ktorý chybu vyhodí; otestovať aj túto chybovú cestu
- admini ponechajú `@sentry/vite-plugin` v devDependencies (je voliteľný peer common-admin, v ich `vite.config.mts` sa už priamo neimportuje)
- testy: node testy pre `./vite` (`src/test/vite/**` v `vitest.config.node.mts`) a vylúčiť ich z browser sady (`vitest.config.mts` dnes vylučuje len `src/test/eslint/**`)
- hneď po kroku 2b: zabaliť (`SKIP_PLAYWRIGHT_INSTALL=true yarn pack`) a v čistom projekte overiť import `@anzusystems/common-admin/vite` (`files`, `exports`, deklarácie, voliteľný peer), ešte kým na ňom nestavajú admini
- skrytosť ostáva: mapy `hidden`, upload do Sentry, zmazanie po uploade; mapy knižnice so zdrojákmi sú aj dnes v npm balíku a repo je verejné
- `package.json`: `exports["./vite"]`, `files` + `src/vite/**`; `copy.sh` kopíruje aj `src/vite` (ako `src/eslint`); docs `doc/guide/installation.md`
- funguje aj po kroku 3 (`preserveModules`) — plugin obslúži každý súbor v `dist`
- **Overenie:** v každom admine build so Sentry premennými **do dočasného release** cez override voľby `anzuSentry` (napr. `release: { name: 'verify-<sha>', finalize: false }`, po overení release v Sentry zmazať) — plugin inak v projektoch `petitpress/anzu-admin-*` vytvorí a finalizuje release, čo ovplyvní „resolved in next release“; alternatíva: samostatný testovací projekt (upload aj mazanie overiť v tom istom výstupnom adresári, do ktorého sa builduje) → JS nemá `sourceMappingURL`, upload prebehol, v adresári nezostala žiadna mapa; mapa pred zmazaním odkazuje na `src/**` knižnice so `sourcesContent`. Po kroku 3 (`preserveModules`, ~786 modulov) vypísať emitované JS moduly knižnice so susednou mapou a nenamapované výnimky a overiť frame z niekoľkých rôznych modulov vrátane vendorovaného; jedna zachytená udalosť z knižnice sa v Sentry rozbalí na pôvodný `.vue`/`.ts`. Skúška na admin-blog overila zreťazenie (so `sourcemap: true`), nie skrytie.

**Kritériá prijatia nového merania** (základ: po kroku 2 a UPRATOVANÍ, s opraveným cropperom). - varianty `preserveModules` mali neinlinovaný placeholder (úspora kroku 2 je v nich; krok 3 sám voči neinlinovanému základu: cms −4,1 %, dam −17,9 %, ugc −23,4 %)

### Admini — chunk pravidlá
- **`includeDependenciesRecursively` rozhodnúť explicitne a zmerať oba varianty vo všetkých 6 adminoch:**
  - `true` (predvolené): skupina je zmiešaná štartová skupina (common-admin + Vue, Vuetify, Axios, …) — posúdiť cache (zmena ktoréhokoľvek zneplatní chunk) a vzťah k existujúcim skupinám `vue-core`/`vuetify`/vendor; cykly medzi chunkami zatiaľ žiadne
  - `false`: len moduly common-admin; otestovať s `preserveEntrySignatures` a `strictExecutionOrder`, sledovať TDZ a cykly medzi chunkami
  - rozhodnutie podľa merania, nie podľa doterajších čísel
- **cms, dam, ugc:** odstrániť vetvu `return 'common-admin'`. dam: pravidlo `vendor-utils` hľadá `node_modules/uuid/` a `node_modules/rusha/` — na cesty `…/common-admin/dist/vendor/…` by sedieť nemalo, overiť v skutočnom builde podľa vyriešených ID modulov a výnimku pridať len pri preukázanej kolízii.
- **blog, forum, inhouse:** skupina podľa merania (blog: +14 KB gzip zisk so skupinou).
- **ugc:** `optimizeDeps.exclude` nerušiť naslepo — dev reload overiť s pre-bundlingom aj bez.
- **eslint adminov:** `eslint.config.mjs` (cms ~38-55, vo všetkých 6) regexom číta `commonAliases` z `dist/common-admin.d.ts` a pri nezhode potichu vráti `[]` — brána: kontrola, že nájdené aliasy obsahujú aspoň `ABtnPrimary`, `ABtnSecondary`, `ABtnTertiary`, `ABtnIcon`, inak chyba.
